- **queue:** the governance-sensitive gate in `scripts/ops/pr-babysitter.sh` now reads only the `review` runs tagged for the PR it is deciding (`unitares-review:<pr>:<head>`). Two open PRs on one head share their check runs, and the newest run on the head used to decide, so another PR's two-family pass could hide this PR's operator waiver. A head that carries only other PRs' runs now counts as not yet reported. The same now holds for every check the queue reads from a PR's check rollup (required, failed, pending, parked): the rollup is the head's and holds every PR's runs, so for each PR it may act on, the queue replaces the rollup's `review` entries with that PR's own runs. Another PR's pass no longer hides this PR's findings, and another PR's findings or unreviewed run no longer hold this PR back. The runs are read with `filter=all`, since GitHub otherwise returns only the newest run of each name. Before arming, the queue also re-reads the PR body, so an `Expected effect:` line removed after the tick began stops the arm.
