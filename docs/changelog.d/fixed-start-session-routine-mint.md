- **start_session:** a default `start_session(force_new=true)` now returns the routine shape for the two common mint classes that were still getting the full onboard record a second time under `raw_governance` (4.4-5.2 KB). One is a fresh uuid on a thread earlier sessions occupied (`sibling_locus`, e.g. behind a shared IP:UA fingerprint). It keeps `state_summary.predecessor_uuid`, adds `state_summary.episode_fork_kind`, and keeps the sentence saying co-location does not establish lineage. The other is a named mint, whose `resident_registration` verdict is lifted in compact form (`status`, `on_roster`, and for `not_on_roster` a short `detail`: what it costs, that this identity cannot gain the tags, and the fix: add the name to the roster, restart, mint fresh). A written bootstrap ack is lifted whole. Measured on the real onboard handler: sibling 4,411 → 1,461 B, named 4,488 → 1,424 B, named sibling 5,229 → 1,733 B; the anonymous position-1 mint is unchanged at 1,152 B. Budgets are now per class: 1,200 B anonymous, 1,550 B sibling, plus up to 300 B per lifted notice. A declared, provisional or rejected lineage, any spawn reason other than the default `new_session` (including `explicit` with no parent), a sibling whose earlier nodes were pruned (no `predecessor_uuid` to lift), a missing or unknown fork kind, a label rename, a deprecation, `temporal_context` and any unknown key still keep the whole record, and `response_shape_reason` now names the field that kept it (absent when a plain mint asked for `response_mode="full"`). A root-node mint with a non-default spawn reason and no parent (classified `identity_lineage`) now keeps the whole record too; it was treated as routine before (#2473).
