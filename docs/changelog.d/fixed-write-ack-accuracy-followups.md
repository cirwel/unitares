- **agent response envelopes:** two accuracy follow-ups to the write acknowledgements that omit `raw_governance` by default (#2439). First, `store_finding` and `update_finding` inject their action (`store`, `update`) only when the caller sent none, and an explicit `action` wins. The `/mcp/` schemas of these aliases do not declare `action`, but REST and stdio pass it through, so a call such as `update_finding(action="details", discovery_id=...)` runs that other `knowledge` action. The envelope used to treat the result as an update ack: it dropped the payload the caller asked for and pointed them at the details read they had just made. The omission now applies only when the resolved action is the alias's own, and any other action's response keeps its payload under `raw_governance` with no omission hint. Second, the `record_result` hint said an outcome's full payload "cannot be read again". That is true only for an outcome recorded without a `prediction_id`. A prediction-bound outcome is idempotent, and its digest does not cover `response_mode` or `include_semantics`, so repeating the identical call with `response_mode="full"` returns the stored outcome in full (`idempotent_replay: true`) and records no second outcome while the binding is retained. The hint for a prediction-bound outcome now names that route, and says that a changed outcome is refused with `PREDICTION_REUSE_CONFLICT`. It also keeps the warning that a repeat without a `prediction_id` records a second outcome. The hint for an unbound outcome is unchanged. The integration guide, the manual and the governance-lifecycle skill say the same. The acks still do not set `raw_governance_available`, because no read returns the omitted payload. No input schema changes, so the interface contract version and digests are unchanged (#2457).
