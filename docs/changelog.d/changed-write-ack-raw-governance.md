- **agent response envelopes:** the write aliases `start_session`, `store_finding`, `update_finding` and `record_result` no longer repeat their canonical payload under `raw_governance` by default, extending the omission the read aliases and routine `sync_state` already had. Each acknowledgement keeps what a caller needs next: `success`, `next_action`, `agent_uuid` and `client_session_id`; for `start_session`, `agent_id`, `display_name`, `continuity_token` (when one is issued), onboard's mint-time warnings when present (`resident_registration` status, with its remedy text when the outcome may not be what was asked for; `label_renamed`; a compact `bootstrap` result), and a compact `identity_assurance` (tier, score, `caller_proven`, `proof_origin`, `baseline`) in `state_summary` (`session_resolution_source` and `continuity_token_supported` appear only in the full-mode payload, which keeps `raw_governance`); `discovery_id` and write-time warnings (failed supersession, truncation, anonymous writer, unclassified closure) for the finding writes; and `outcome_id`, `is_bad`, `idempotent_replay`, `unverified_fields` and any handler `identity_warnings` for `record_result`. `raw_governance_hint` names the route to the full payload and never suggests repeating the write: `response_mode="full"` on `record_result` (its older `include_semantics` spelling still works), a `knowledge(action="details", discovery_id=...)` read for the finding writes (the canonical `knowledge` tool also returns their payload directly; `response_mode` is not a full request on these two aliases, because canonical validation defaults `knowledge`'s `response_mode` to `"full"` and the envelope cannot tell a caller's request from that default, and their `/mcp/` schemas do not declare it), and an `identity(client_session_id=...)` read for `start_session`, with a warning that a second `start_session(force_new=true)` mints a second identity. `start_session(response_mode="full")` on the first call still returns the payload on every transport; onboard's older `verbose` spelling does the same over REST and stdio only, because the `/mcp/` argument model for `start_session` does not declare it. A write whose record id the envelope cannot lift keeps the canonical payload. `request_review` is unchanged: its acknowledgement carries the review itself. Identity refusals and error payloads still pass through whole. Audit attribution for `start_session` now also reads the top-level `agent_uuid`. Measured on the same canonical payloads re-rendered locally (2026-09-25, recorded acknowledgements, 4-5 per alias, p50): `store_finding` 5,412 B to 1,000 B, `update_finding` 5,678 B to 1,444 B, `record_result` 5,505 B to 1,337 B, `start_session` 4,566 B to 1,691 B (measured before the mint-time warnings were lifted; an ack carrying one grows by that block, up to about 640 B for an off-roster `resident_registration` with its remedy text). No input schema changes, so the interface contract version and digests are unchanged.
