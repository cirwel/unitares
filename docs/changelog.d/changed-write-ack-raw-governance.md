- **agent response envelopes:** the write aliases `start_session`, `store_finding`, `update_finding` and `record_result` no longer repeat their canonical payload under `raw_governance` by default, extending the omission the read aliases and routine `sync_state` already had. Each acknowledgement keeps what a caller needs next: `success`, `next_action`, `agent_uuid` and `client_session_id`; for `start_session`, `agent_id`, `display_name`, `continuity_token` (when one is issued), `continuity_token_supported`, `session_resolution_source`, and a compact `identity_assurance` (tier, score, `caller_proven`, `proof_origin`, `baseline`) in `state_summary`; `discovery_id` and write-time warnings (failed supersession, truncation, anonymous writer, unclassified closure) for the finding writes; and `outcome_id`, `is_bad`, `idempotent_replay`, `unverified_fields` and any handler `identity_warnings` for `record_result`. `raw_governance_hint` names the route to the full payload and never suggests repeating the write: `response_mode="full"` on `start_session` and `record_result` (their older `verbose` and `include_semantics` spellings still work), and a `knowledge(action="details", discovery_id=...)` read for the finding writes, whose `/mcp/` schemas declare no response mode. A write whose record id the envelope cannot lift keeps the canonical payload. `request_review` is unchanged: its acknowledgement carries the review itself. Identity refusals and error payloads still pass through whole. Audit attribution for `start_session` now also reads the top-level `agent_uuid`. Measured on the same canonical payloads re-rendered locally (2026-09-25, recorded acknowledgements, 4-5 per alias, p50): `store_finding` 5,412 B to 1,000 B, `update_finding` 5,678 B to 1,444 B, `record_result` 5,505 B to 1,337 B, `start_session` 4,566 B to 1,691 B. No input schema changes, so the interface contract version and digests are unchanged.
