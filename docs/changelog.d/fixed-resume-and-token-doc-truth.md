- **identity docs:** `onboard`'s `resume` description, which also shows on the `start_session` alias, no longer lists `continuity_token`, `agent_id` and `name` as resume signals. A name is never looked up (name-based reconnection was removed 2026-04-17), and a `continuity_token` without `force_new` is refused by S1-c. The text now says only what holds in every case: resume reuses this session's existing identity when the call proves it owns that binding (for example with its `client_session_id`), and the full rules (S13, the IP:UA pin check) are in `docs/ontology/identity.md`. It also names the `identity(agent_uuid, continuity_token, resume=true)` rebind. The lifecycle skill no longer says S1-a accepts token resume during a deprecation window. Interface contract 1.18.0: descriptions only, no parameter changes.
