- **Credentials only for a caller that proved ownership.** `identity()` and `onboard()` return the agent's `client_session_id` and a signed `continuity_token`, and either one lets the holder act as that agent. They were returned to any call the server matched to an agent, including a match by inference: an onboard pin keyed on the User-Agent alone, a transport fingerprint, or a name or unverified `agent_id` on onboard. On a Docker bridge or behind a tunnel every client arrives from one address, and a User-Agent is whatever a client sends, so one client could obtain another's credentials. Under strict identity, the default, credentials now go only to a mint, a session or token the caller itself sent, a UDS substrate attestation, or an operator token. An inferred `identity()` returns `client_session_id: null`, no token, and `credentials_withheld` with the reason, and skips binding the stable session for that caller; an inferred `onboard()` resume is refused with `resume_proof_required` before anything is bound. The SDK, the governance plugin, the Hermes host adapter and the reference residents mint with `force_new`, resume with their own session or token, or attest over UDS, so they are unaffected. `UNITARES_CREDENTIAL_ISSUANCE=log` issues as before and logs each response the rule would withhold, for finding dependent clients before enforcing. A deployment with `STRICT_IDENTITY_REQUIRED=false` keeps its permissive behavior. This closes the inference routes only: a legacy `client_session_id` of the form `agent-{uuid[:12]}` can still be computed from an agent's public UUID and sent as the caller's own session, which needs a session id that cannot be derived from the UUID.
