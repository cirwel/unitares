- **skills (freshness stamps):** an agent whose harness gives its command a pseudo-terminal can no longer stamp a skill under the git user's name. #2529 refused `scripts/client/check-skill-freshness.sh --stamp` without `SKILL_ATTESTATION_VERIFIER` when stdin was not a terminal, and kept the git `user.name` fallback for a person at one. A TTY on stdin was the only test for a person, and it does not hold for every agent: Codex's `exec_command` takes `tty: true` and Hermes' terminal tool takes `pty`, so an agent command run either way still recorded the operator's git name as its verifier. The stamp now also takes the caller for an agent or a job when a variable an agent harness or CI runner sets is present: `CLAUDECODE` (Claude Code), `CODEX_THREAD_ID` and `CODEX_CI` (Codex), `AI_AGENT` (Claude Code and Hermes) and `CI` (CI runners). Each was seen set before it was listed: in a Claude Code shell, in the `env` output recorded in Codex session transcripts, in the command wrapper of Hermes' terminal tool, and in this repository's Tests workflow log. An empty, `0` or `false` value does not count, so a person who exports `CI=false` keeps the fallback. The refusal names the variable it found, and says separately when stdin is not a terminal. A person at a terminal with none of these variables set is unaffected, and a caller that sets `SKILL_ATTESTATION_VERIFIER` is accepted as before, marker or not. A harness that sets none of these variables and gives its command a terminal still reaches the fallback; other harnesses (Cursor, Gemini CLI, Antigravity) were not checked. Existing attestations are not rewritten (#TBD).
