- **skills (freshness stamps):** a skill attestation no longer credits the git user with a re-check that an agent or a job made. When `SKILL_ATTESTATION_VERIFIER` was unset, `scripts/client/check-skill-freshness.sh --stamp` recorded the repository's git `user.name` as the verifier. Every agent on an operator's machine commits under that one name, so an agent's stamp read as the operator's own re-check, and the record could not tell the two apart: of the 120 attestations dated 2026-09-26 in master's history, 99 carry the operator's git name and 21 name an agent. A stamp now takes its verifier from `SKILL_ATTESTATION_VERIFIER` when it is set. Without it, a person at a terminal (stdin is a TTY) still falls back to git `user.name`, and the stamp says so. Any other caller, and a terminal where git has no `user.name` (which used to record the verifier as `unknown`), is refused with exit code 2 before any skill is touched: nothing is written, and the message names the variable and the command to re-run. The STALE hint the check prints now includes the variable, so an agent copying it stamps under its own name. The check itself, `--prune` and `--migrate` record no verifier and are unchanged, so CI and the release-cut prune are unaffected; no automated caller in this repository stamps. Existing attestations are not rewritten. A harness that runs an agent under a pseudo-terminal still reaches the git fallback (#2529).
