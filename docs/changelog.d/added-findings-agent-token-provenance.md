- **Server-verified finding provenance (`findings` agent token scope):** `UNITARES_HTTP_AGENT_TOKENS` now supports the `findings` scope for `POST /api/findings` (isolated from `checkin`/`outcome`/`knowledge_store` on `POST /v1/tools/call`). `POST /api/findings` strips any caller-supplied `provenance_verified` and `verified_actor_agent_uuid` fields and stamps them server-side (`provenance_verified: true` + canonical `verified_actor_agent_uuid` only for a valid per-agent `findings`-scoped token; `false` / `null` for trusted-network, dashboard-session, and shared static bearer callers), partitions finding dedup by provenance trust tier and verified actor UUID so unverified or other-actor posts cannot suppress verified findings, and preserves both top-level fields through event storage, `/api/events` (in-memory and audit-DB backfill), and WebSocket broadcast. `agents/common/findings.py` and Vigil accept optional `UNITARES_FINDINGS_AGENT_TOKEN` with safe fallback to `UNITARES_HTTP_API_TOKEN` / `UNITARES_MCP_BEARER_TOKEN` when unset.
