- **BEAM node cookies no longer appear on any command line.** The agent-orchestrator and lease-plane start scripts passed their Erlang cookie with `elixir --cookie`, which puts it in `beam.smp`'s argv, readable by any process listing; node access is arbitrary code execution, and the orchestrator's cookie reached an agent transcript that way on 2026-10-15. Each `start.sh` now writes the cookie to a private file (`$XDG_STATE_HOME/unitares/beam/<service>/.erlang.cookie`, directory 0700, file 0400), boots the VM with `HOME` pointing there (with `MIX_HOME`/`HEX_HOME` pinned), starts epmd with a clean environment, and `NodeDistribution` restores the real `HOME` before starting the named node, so the node holds the private cookie from its first instant. `scripts/ops/beam-attach.sh` and the lease plane's `hot-reload.sh` give their client node a private `~/.erlang.cookie` (removed on exit) instead of `--cookie`. Rejected after testing: `-args_file` and `ERL_AFLAGS` (expanded back into argv) and a throwaway boot cookie replaced at runtime (a watcher could connect in the gap). Takes effect when each service restarts.
