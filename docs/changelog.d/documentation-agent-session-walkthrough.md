- **docs: agent session walkthrough.** `docs/guides/AGENT_SESSION_WALKTHROUGH.md` shows one task across two processes: every call an agent makes, and the response a fresh Docker quickstart install returned, captured over MCP Streamable HTTP rather than written by hand. Process A searches shared memory before it has an identity, starts with `start_session(force_new=true)`, confirms threading with `check_working_state`, records a finding, checks in, grades the check-in against a test result, closes the finding with `closure_class="fix_verified"` and its evidence, and exits. Process B finds A's finding before redoing the work and declares A as its predecessor with `spawn_reason="explicit"`. Two steps that the integrating-agents chapter does not spell out are shown with the server's own message for the case where they are skipped. First, `record_result` needs the `prediction_id` from the `sync_state` it grades; without it the outcome is recorded but excluded from calibration. Second, a clean exit calls `agent(action="release_presence")`; without it a successor that declares the process as its parent within the presence TTL is refused as co-located (`rejected_coincidental`). The manual's integrating-agents chapter and the docs index link to the walkthrough.
