- **identity: the identity surface's events reach the broadcaster again:** `_broadcaster()` in `src/mcp_handlers/identity/handlers.py` and `persistence.py` imported `broadcaster` from `src.broadcaster`, a name the module never defined (the singleton is `broadcaster_instance`). The accessors swallowed the ImportError and returned None, so every event they gate was skipped since those accessors landed in April 2026 (#70, #78): `identity_hijack_suspected` from the PATH 0 continuity-token gate (handler and middleware), the PATH 1 fingerprint and token-mismatch checks, the synchronous fingerprint check and the PATH 2 IP:UA pin check, plus `pg_session_collision` and `resident_fork_detected`. The warning log lines were written all along, but the WebSocket stream, `audit.events` and anything subscribed to them saw nothing. Every emission test patched the accessor with a mock, so none of them noticed. Both accessors now return `broadcaster_instance`, and a new test calls them unpatched and holds every `from src.broadcaster import ...` under `src/` to a name the module defines. What changes for an operator: these events now appear on `/ws/eisv`, in `/api/events` and in `audit.events`. `identity_hijack_suspected` fires once per fingerprint mismatch in the default `log` mode, most of which come from benign same-agent twins, so a relay that posts every broadcaster event to chat (the Discord bridge does, with no repeat suppression for this type) posts one message per mismatch unless it suppresses or de-duplicates the type. No gate decision, tool description, input schema or interface contract changed (#TBD).
