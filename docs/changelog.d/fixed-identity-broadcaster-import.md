- **identity: the identity surface's events reach the broadcaster again, without holding up identity resolution:** `_broadcaster()` in `src/mcp_handlers/identity/handlers.py` and `persistence.py` imported `broadcaster` from `src.broadcaster`, a name the module never defined (the singleton is `broadcaster_instance`). The accessors swallowed the ImportError and returned None, so every event they gate was skipped since those accessors landed in April 2026 (#70, #78): `identity_hijack_suspected` from the PATH 0 continuity-token gate (handler and middleware), the PATH 1 fingerprint and token-mismatch checks, the synchronous fingerprint check and the PATH 2 IP:UA pin check, plus `pg_session_collision` and `resident_fork_detected`. The warning log lines were written all along, but the WebSocket stream, `audit.events` and anything subscribed to them saw nothing. Every emission test patched the accessor with a mock, so none of them noticed. Both accessors now import `broadcaster_instance` and hand it out behind a thin wrapper whose `broadcast_event` schedules the broadcast as a tracked background task and returns at once. The broadcaster awaits its WebSocket fan-out (up to 2 s per stalled client plus 2 s to close it), and the REST `client_session_id` corroboration lookup gives identity resolution 0.5 s, so an awaited event could have turned a stalled dashboard tab into a failed corroboration; a telemetry event now never decides whether a resolution finishes. The synchronous fingerprint check, which cannot await, used a bare `loop.create_task` that the loop references only weakly; it now schedules through `create_tracked_task` as well. New tests call the accessors unpatched, hold every `from src.broadcaster import ...` under `src/` to a name the module defines, and time a fingerprint mismatch against a stalled fan-out. What changes for an operator: these events now appear on `/ws/eisv`, in `/api/events` and in `audit.events`. `identity_hijack_suspected` fires once per fingerprint mismatch in the default `log` mode, most of which come from benign co-resident twins, so a relay that posts every broadcaster event to chat (the Discord bridge does, with no repeat suppression for this type) posts one message per mismatch unless it suppresses or de-duplicates the type. No gate decision, tool description, input schema or interface contract changed (#2559).
