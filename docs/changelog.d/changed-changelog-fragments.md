- **changelog:** entries now arrive as one new file per pull request under `docs/changelog.d/` (`<section>-<slug>.md`, body = the entry) instead of an edit to `## [Unreleased]`. Every PR used to write into the same subsection, so each merge conflicted every other open PR with an entry, and resolving the conflict re-keyed its review. The release cut folds the fragments in with `scripts/dev/changelog_assemble.py` before the version header is written, so `changelog_coverage.py` still checks the assembled entry; it now also fails a release tree that still holds a fragment. The Release Seams workflow validates fragments on every PR and fails an ordinary PR that edits `## [Unreleased]` directly (release trees and dependabot exempt; released entries stay editable for errata and maintenance forward-merges). Existing `[Unreleased]` entries are unchanged.
