- **eisv:** rows can now be partitioned by the instrument that produced them. Every `core.agent_state` row carries `state_json.eisv_instrument` (`eisv.instrument.v1`): the instrument era, a hash of the effective configuration (dynamics parameters, value-affecting flags, class-calibration tables, resident roster, decision thresholds), the build sha, and the monitor's check-ins since its instrument last changed, so the transient after a restart or a maths change is visible per row. `config/eisv_instrument_eras.json` lists the 24 known changes since March for older rows, each with how its time is known and an ambiguity interval. `src/eisv_eras.py` refuses analysis windows that cross a change unless given a reason and splits windows per era; `scripts/analysis/basin_conjunct_binding_read.py` now defaults to the current era. A change to the golden trajectories must add a registry entry (`tests/test_eisv_instrument_eras.py`). The stamp is provenance only and is fail-open; nothing on the decision path reads it.
