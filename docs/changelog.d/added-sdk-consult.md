- **sdk:** `UnitaresClient.consult()` and `SyncGovernanceClient.consult()` call the server's `consult` tool and return a new `ConsultResult` (`advice`, `status`, `consultation_id`, `completion`). A refusal raises `GovernanceToolRefused`; the sync client now raises that type for every refused call too (it raised the parent `GovernanceConnectionError` before, so existing handlers still catch it). `effort` is omitted unless given, so the server infers it from `host_id`. A consultation is sent once and never retried, because after a timeout the first may still be running: `call_tool` gains `retry=False` for that (one attempt only) on the async client and on both sync transports, where it also stops the REST 503 retry because a proxy may have forwarded the first request. On the MCP transport the HTTP client's own `timeout` (30s by default) still bounds the call, so a long consultation needs a client built with a larger `timeout`. `call_model()` on both clients now emits a `DeprecationWarning` pointing at `consult()`, matching the server tool's deprecation; it still works and is still the only way to set `model`, `temperature` or `max_tokens` on an HTTP host. No SDK version bump here.
