- **background tasks:** loops that catch their own failures no longer log them at DEBUG, which the server never writes. The matview refresh, audit partition maintenance, silence check, resident pause check, the silence probe's KG finding write and close, and the server log rotation (whose copy or truncate failure was logged at DEBUG, leaving the log to grow) now record each run in `src/background_task_health.py`. The first failure, and each change of error, logs a WARNING; the same error repeating stays at DEBUG, and recovery logs INFO. The health check gains a `background_tasks` entry (last success, last error, failures in a row per task) that reads `warning` while any task's latest run failed. The doctor's new `background_task_failures` check reads it from `/health/deep`, WARNs instead of passing when that snapshot is stale, and SKIPs, saying why, when it cannot read it.
