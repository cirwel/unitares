- **background tasks:** loops that catch their own failures no longer log them at DEBUG, which the server never writes. The matview refresh, audit partition maintenance, silence check, resident pause check, and the silence probe's KG finding write and close now record each run in `src/background_task_health.py`. The first failure, and each change of error, logs a WARNING; the same error repeating stays at DEBUG, and recovery logs INFO. The health check gains a `background_tasks` entry (last success, last error, failures in a row per task) that reads `warning` while any task's latest run failed. The doctor's new `background_task_failures` check reads it from `/health/deep` and SKIPs, saying why, when it cannot.
