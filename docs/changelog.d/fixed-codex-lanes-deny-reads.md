- **Codex lanes can no longer read the operator's files.** Codex's legacy `--sandbox read-only` denies writes but reads the whole disk, and the lanes return the model's answer to the caller, so a prompt, or text injected into one such as a diff or a thesis under review, could have the agent read credentials and hand them back (verified 2026-10-15 with a canary file in the home directory). The codex host adapter (app-server client and exec fallback) and the dialectic reviewer's codex backend now run with `codex_app_server_client.lane_config_overrides`: a permission profile, under a fresh random name per launch so no configuration can pre-populate it, that denies reads except the platform's minimal runtime paths and the directories holding the codex binary, writes denied, commands seeing only an allow-list of core environment variables (`include_only`, which also drops anything the operator's `shell_environment_policy.set` injects), no hooks, plugins, apps, browser or computer use, and every MCP server the operator's codex config declares switched off by name (`-c` deep-merges tables, so `mcp_servers={}` would have left them running). Every lane runs in a fresh empty directory outside any repository, so no project `.codex/config.toml` or instructions load. Lanes that load the operator's config enumerate the MCP servers still enabled (`codex mcp list`) and switch each off by name, refusing to run if any stays enabled. The app-server thread no longer sends `sandbox`, which would select the legacy sandbox. Host adapters refuse any sandbox other than `read-only`. Verified end to end on all three paths with a file canary and an environment canary: neither leaked, and an ordinary question still answers. The reviewer keeps the operator's codex model and reasoning effort. Any administrator codex configuration (`/etc/codex/config.toml`, managed config, requirements, macOS MDM preferences) refuses the lanes, since managed layers outrank `-c` overrides; an npm-installed codex also grants its `@openai` package scope so the sandbox can start the native binary. Before any codex lane runs, a `codex sandbox` probe (no model call) must fail to read a file outside the profile while still running a harmless command, so an older codex that ignores the profile keys refuses rather than runs unconfined; the result is cached per binary and modification time.
