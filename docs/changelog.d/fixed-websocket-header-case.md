- **`/ws/eisv` authentication no longer refuses legitimate WebSocket clients because of header casing.** The ASGI specification requires lowercased header names, and Starlette's `Headers` relies on that when it looks a header up. uvicorn's websockets-sansio protocol, which serves the live EISV feed, instead passes the client's casing through unchanged. A browser or library that sends `Authorization`, `Origin` or `Cookie` with a capital letter therefore had that header silently ignored on the WebSocket handshake. As a result, a valid bearer token was refused, the passkey `Origin` pin never matched, and a signed-in dashboard session cookie was not seen, so the dashboard's live feed could fail for a signed-in operator reaching the server through the public listener. The server now lowercases WebSocket header names in a small middleware registered outermost, before any check reads them. HTTP requests already arrive lowercased and are not touched. The failure was fail-closed: no request was ever wrongly admitted, so this restores access for legitimate clients and changes no trust decision. Operators do not need to change any configuration.
