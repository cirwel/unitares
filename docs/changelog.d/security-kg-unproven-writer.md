- Under strict identity, knowledge writes refuse an `agent_id` the call has not proven (GHSA-4m7p-grgw-vgmh). The REST gate passes an unbound call whose `agent_id` is not UUID-shaped, and below high severity nothing then checked it: an unbound caller could store or note under any invented name (each with its own store budget), update or close another agent's low and medium findings, and supersede, clean up, synthesize, promote or audit without proof. Every identity-gated knowledge handler now refuses that case with the typed `identity_required` refusal. Supersede, cleanup, synthesize, promote and audit, which have no anonymous writer, refuse every unbound call and accept a server-inferred binding only for a substrate resident. The REST strict-identity gate also judged only the outer call, while dispatch unwraps `kwargs` after it: a write wrapped in a read, or an inner null over an outer name, passed the gate unbound on any identity-required tool. It now judges the call at every depth dispatch unwraps to, and a wrapped read still serves unbound. Bound callers, the anonymous writer on an inferred binding, and `STRICT_IDENTITY_REQUIRED=0` are unchanged.
