- **test isolation:** the test suite no longer reaches the live Redis. `tests/conftest.py` isolates PostgreSQL, but the Redis client connects to `REDIS_URL` (default `redis://localhost:6379/0`, the operator's live session store) the first time anything calls `get_redis()`, and identity code reaches it from paths a test does not obviously exercise: shadow-pin reads in `derive_session_key`, and the metadata-cache invalidation in `set_agent_label`, which one test run in this batch used to send a `DEL` for a key it had just minted. A new repo-root `conftest.py`, which covers both `tests/` and `agents/`, points `REDIS_URL` at `redis://127.0.0.1:1/0` before any test module imports, and drops `REDIS_SENTINEL_HOSTS`. An unmocked call then fails fast into the client's no-Redis branch. Tests that exercise the client use fakeredis or patch `REDIS_URL` themselves, which still wins; `test_redis_resilience.py`'s default-value test now removes `REDIS_URL` explicitly rather than relying on the developer's shell. Set `UNITARES_TEST_LIVE_REDIS=1` to opt out deliberately. An audit-hook probe over the full suite counted 0 connections to ports 6379 and 26379, and 15 to the guard's port 1 in the identity suites alone (#TBD).
