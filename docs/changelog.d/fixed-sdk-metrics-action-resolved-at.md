- **SDK metrics and finding closes:** `get_metrics().action` is now the policy action (`proceed` or `pause`) at every verbosity, as its docstring and the `MetricsResult.action` field comment already promised. The resolver used to read the canonical lifecycle word (`raw_governance.last_decision_action` or `verdict.decision_action`) before the envelope's `action_summary.action`, so the same agent read `proceed` at the default tier but `guide`, `resumed` or `not_paused` at `standard` and `full`, where `raw_governance` rides along. It now reads `action_summary.action` first and maps a canonical lifecycle word the way the server's envelope does (`_POLICY_ACTION`, pinned to `envelope_step._ACTION_ALIASES` by a test), so callers that compare `action == "proceed"` behave the same whatever tier they request. `resolved_at` is now stamped only on the transition into `resolved`. The closure note's follow-up call repeats the closing status, because a non-owner of a high or critical finding may append resolution notes only together with it, and that repeat used to move the finding's resolution time to the moment of the follow-up. Both are review follow-ups to #2479, which merged before they could land on its branch (#2482).
