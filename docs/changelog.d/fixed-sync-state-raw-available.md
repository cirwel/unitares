- **check-ins:** a bounded `sync_state` response (the default compact or mirror check-in, and the `compact`, `mirror`, `standard` and `minimal` modes) no longer sets `raw_governance_available: true`. That flag promises a re-call that fetches the omitted payload by reading, which is what it means on `check_working_state` and `search_shared_memory`, whose hint names the same read at a fuller tier. A check-in has no such read. Its omitted payload is that check-in's decision (reason, margin, policy gates, enforcement, `prediction_id`, warnings), and `check_working_state(verbosity="full")` and `get_governance_metrics` report the agent's current state rather than what one check-in decided. The only route to that payload was `response_mode="full"` on the next `sync_state`, which records another check-in, so an agent that trusted the flag and re-called to read it would write again. The flag is now set only by the two read aliases, as a routine `start_session` and the `store_finding`, `update_finding` and `record_result` acknowledgements already did not set it. `raw_governance_hint` is unchanged and still names `response_mode="full"` on the next `sync_state`. A `sync_state` with `response_mode="full"` still carries the payload under `raw_governance`. The integration guide and the manual say so. No tool description or input schema changes, so the interface contract version and digests are unchanged (#TBD).
