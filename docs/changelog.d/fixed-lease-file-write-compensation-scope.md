- **lease plane `file_write`:** compensation no longer removes an entry the refused write did not create. When the pre-image was absent and a FIFO, socket, device or hard-linked name appeared at the leased path before the write, the write refused it and compensation then unlinked it and tombstoned the effect. `EffectFileOps.rm/1` now removes only a regular file with a single link, so such an entry stays in place and the effect is quarantined for the operator, as for a planted link. An existing file the service may write but not read is overwritten again, as before the file-confinement change: the overwrite opens the leaf write-only instead of read-write. A FIFO with no reader fails that open with `ENXIO`, which is reported as `:not_regular_file`.
