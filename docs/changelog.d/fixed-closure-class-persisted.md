- **closure_class is stored; update_finding declares it; interface contract 1.20.0:** `closure_class` and `closure_evidence`, validated since #1752, are now written by every knowledge update path (the AGE SQL sync and graph node, the AGE SQL-only fallback, the Postgres backend) and read back by every converter; until now each path copied a fixed column set that left them out, and no live row carried a class. Migration 071 widens 064's `discoveries_closure_class_requires_closed` to admit a class on `archived` and `cold` as well as the closing statuses, so the KG lifecycle can still archive a classified finding and move it to cold (under 064 the AGE backend would have left such a row `resolved` forever, logging the refusal every run, and the Postgres backend would have lost the rest of the run). An update that reopens a finding (`open` or `disputed`) clears both fields on every path, including writers that know nothing about classes, such as dialectic's resolution. A class sent without a status is judged against the stored status and refused on an open finding with `INVALID_PARAM` before storage (otherwise, with the class now written, the constraint would refuse it there and the AGE backend would report "Discovery not found"); a class alone now classifies a finding closed earlier; evidence without a class, evidence that is not an object, or evidence over 8 KiB as stored JSON is refused instead of dropped (on AGE an oversized property would have failed the whole update as "Discovery not found"); a non-owner of a high or critical finding may set a class only in the call that closes it, and the refusal says so and names that call instead of "Retry with status only", which dropped the class (it says the same for `resolution_notes`). The update response's `closure_class` is the value read back from the record, with a `closure_class_note` if it differs from what was sent, and the note on an unclassified close names `update_finding(discovery_id=..., status=..., closure_class='...')` with each class's evidence keys. `knowledge(action='details')` returns the class and its evidence (paginated or not), search results carry the class and expanded results its evidence, and the lean search digest is unchanged. The AGE SQL-only fallback, which called `db._pool.fetchval` on an ExecutorPool that has no such method and so failed every update it handled, goes through the backend's connection now. Interface contract 1.20.0: `update_finding` declares `closure_class` and `closure_evidence` with the router's descriptions (before, `/mcp/` dropped both from an `update_finding` call); `knowledge`'s `discovery_type` says store defaults it to `note` (it said "Required"), promote to `insight`, update retypes and search filters, and on `update_finding` it says an omitted type keeps the stored one; `closure_class` says a class may also be set alone on a finding that is already closed, and `closure_evidence` states its bound; `observe`'s `target_agent_id` names the `audit_events` and `outcome_evidence` filters, which match the stored `agent_id` exactly and do not resolve labels (a UUID for most agents, but some audit writers, such as `system` and `sentinel`, are stored by name), `until` names `outcome_evidence` and `agent_ids` the `anomalies` and `aggregate` scope; `dialectic`'s `issue_description` names `action=quick`. Nothing is removed, retyped or renamed; five input digests and the surface digest move. The migration is opt-in at deploy and must land before the code (#2489).
