- **review gate:** a base merge no longer voids a finished review when the PR's own lines are unchanged. The diff key hashes each changed file's blob, so a merge from master that edited text next to a PR's lines moved the key and left the `review` check UNREVIEWED. That covers GitHub's "update branch" for auto-merge and a plain merge of the base. It happened twice on #2499, and on #2519 while it was armed for auto-merge. The gate now treats the earlier keys as the same diff when two things hold. Every merge since must be a clean automatic merge of the base: `git merge-tree` reproduces its tree with no conflict. And the fingerprint of the PR's added and removed lines must be unchanged. Records on those keys, and native Codex reviews of those earlier heads, then count as the head's: the review, its findings, its dispositions and its model families. An open finding stays open until disposed. The check says "carried across a base merge from `<sha>`". A conflict resolution, any edit made in a merge, a new commit, or any change to an added or removed line stops the carry. The local `review`, `record` and `dispose` commands read records the same way.
