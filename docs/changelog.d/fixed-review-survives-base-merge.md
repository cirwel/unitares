- **review gate:** a base merge no longer voids a finished review when the PR's own lines are unchanged. The diff key hashes each changed file's blob, so a merge from master that edited text next to a PR's lines (GitHub's "update branch" for auto-merge, or a plain merge of the base) moved the key and left the `review` check UNREVIEWED. That happened twice on #2499, and on #2519 while it was armed for auto-merge. When no record matches the head's key, the gate now walks back through merge commits whose second parent is on the base. While the fingerprint of the PR's added and removed lines is unchanged, it decides with the earlier key's records. Findings, dispositions and model families carry too, and the check says "carried across a base merge from `<sha>`". A conflict resolution, a new commit, or any edit to an added or removed line stops the carry.
