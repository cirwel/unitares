- **attestation docs:** `EVIDENCE_AND_LIMITS.md`, `SCOPE_AND_THREAT_MODEL.md` and the `drr.v1` decision packet no longer describe resolution attestations as HMAC keyed on each agent's `api_key` as if the deployment used it. That party-HMAC scheme is in the code, but as of 2026-09-25 no resolution record in the maintainer deployment carries a signature keyed on a party's `api_key` under the current scheme: the four 2026 records that carry a signature used a uuid-derived fallback key, forgeable from public data and removed in #2155, and the most recent records carrying two signatures are legacy v1 rows from 2025-12-13 UTC, which cannot be verified. `EVIDENCE_AND_LIMITS.md` also states more precisely what was shelved on 2026-04-19: asymmetric (DPoP-style) keys for agent identity, which party-level non-repudiation would also need, and that remains shelved; the record of that decision does not address server-side signing. `SCOPE_AND_THREAT_MODEL.md` no longer cites that agent-identity decision as a decision to keep the party HMAC, which the code records as still open. Server-side Ed25519 signing exists: as of 2026-09-25 the maintainer deployment's lease attestations use it, and the dialectic resolution receipt (`drr.v1`) is wired, dormant and has issued no receipts. A receipt would attest the deployment's stored record, not either party's intent. The packet also notes that on the peer-review path a paused agent with no key on file gets a `signature_a` keyed on the `api_key` the synthesis submitter supplied, so `both_signatures_present` records that strings were stored, not who held the keys. The consequence is unchanged: a record from this system still cannot be verified by an operator who does not already trust its issuer, and nothing here enables or proposes enabling `drr.v1`. The dormant-capability registry's `drr.v1` row now lists a second principal as its own precondition, alongside custody, a pinning channel, key history and a revocation or transparency policy, and the packet's summary names all five instead of two.
