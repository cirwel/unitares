- **watcher:** a region whose model reply cannot be read is asked for once more, differently, instead of being left unscanned. At temperature 0 the same request returns the same reply, so the retry turns thinking off and holds the reply to the scan envelope as a JSON schema (`SCAN_REPLY_SCHEMA`); on the reference host (gemma4:latest, ollama 0.32.14) the schema alone did not bind at scan size and `think: false` is what made it apply. Measured there over two weeks, 55 of 781 region scans were unusable, 48 of them malformed JSON, most from code copied into `evidence` with its quotes or newlines unescaped. The normal request is unchanged and stays the detector, because thinking off reports different findings: on four regions that parsed both ways the kept findings matched on none. Findings from the retry carry `+constrained` in `model_used` and are left out of pattern precision, as rows from another rule revision are, so adjudicating one never moves a pattern's floor; a recovered region logs a warning and a chunked file logs how many of its regions needed it, and a retry that fails in any way records the original failure exactly as before. A recovered region counts as scanned, so a detector whose normal mode failed everywhere but always recovered would not raise detector-down. Native `/api/chat` only; the review detector and the OpenAI-compatible endpoint are untouched. `WATCHER_CONSTRAINED_RETRY=0` turns it off.
