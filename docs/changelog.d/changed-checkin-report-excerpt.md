- **check-ins:** each `sync_state` check-in now keeps a bounded excerpt of its report text in its state row (`state_json.report_excerpt`), so a later reader can see what the agent said beside the state it was given. Through v3.5.0 the report text was not kept at all, apart from the 500-character summary an auto-recorded outcome stores when the text matches its completion or failure pattern. The excerpt is the agent's own words, not a verified claim: durable claims still belong in a finding. It is at most 500 characters by default (`UNITARES_CHECKIN_EXCERPT_CHARS`, capped at 2000; `0` turns it off), whitespace is collapsed, and a longer text is cut at a word boundary with `…`, so an identifier is never split mid-token. Common credential shapes are redacted before storage: provider tokens, `Bearer` values, `name=value` pairs whose name looks secret, URL passwords and private-key blocks. This is best effort, not a guarantee. The server instructions, product definition, capabilities page, reviewer guide and architecture doc now say this instead of "not retained". Operator decision, 2026-10-23.
