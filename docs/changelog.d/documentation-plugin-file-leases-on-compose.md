- **install:** the install manual now says what the lease plane does for an install that is not the original operator's: with the governance plugin installed, Claude Code and Codex take a lease on each file before editing it and release it afterwards, so a second agent editing the same file in the same checkout is refused instead of overwriting the first. Before governance-plugin#165 the plugin looked for the lease-plane bearer only in the environment or the original operator's secrets path, so on a default Docker Compose install it never took a lease and never said so. The manual now states that the Compose defaults need no setup (the plugin presents the stack's development bearer to the loopback lease plane), that an operator who sets their own `LEASE_PLANE_BEARER_TOKEN` in `.env` must put the same line in `~/.config/unitares/secrets.env` where the agents run, and that the plugin reports at session start when leases are enabled but would not work. `.env.example` carries the same note beside the bearer setting. No server or Compose behaviour changes.
