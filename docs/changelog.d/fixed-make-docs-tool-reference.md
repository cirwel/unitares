- **tool docs:** `make docs` runs again. It had called a `scripts/generate_tool_docs.py` that no longer existed. The generator it meant scanned handler files for decorators: on this tree it found 4 of the 43 registered tools and missed every `action_router` tool. Widening its glob does not fix that model: when #2355 tried it with every category rendered, review found it documenting `register=False` internals as tools (it counts every decorated function) and `consult`'s 480s as the 30s default (it reads only literal timeouts). `scripts/diagnostics/generate_tool_docs.py` now reads the runtime registry, through the same loader as `tool_edge_index.py`, and writes `docs/dev/TOOL_REFERENCE.md`: every registered tool by category, with its identity class, its timeout and a ceiling on each action's (the smaller of the router's and its delegate's, e.g. `dialectic` `request` 105s, `thesis` 90s), its workflow alias and older names (and the transports that still resolve them), and the description `describe_tool` serves, with JSON examples and aligned columns kept verbatim. Both generators now pin `UNITARES_DIALECTIC_REVIEW_BUDGET` and `UNITARES_CALL_MODEL_TIMEOUT` to their defaults before import, so a local override is not committed as if it shipped. The CI `smoke` job and the doctor (`tool_reference_fresh`) check the reference is current; `make docs` now regenerates all four generated docs. `tool_edge_index.py` also stops calling a machine without `mcp` installed a "defect in the tree": a dependency missing at the handler package's own import now gets the install remedy, as one missing deeper already did. And a handler subpackage that raises while it imports (anything under `middleware/` or `updates/`) is now reported as a failed module; the package walk used to re-raise it and crash both generators (#2425).
