- **dialectic:** a converged peer-review synthesis no longer signs party A's slot with the synthesis caller's `api_key`. When the paused agent had no key on file, `handle_submit_synthesis` fell back to the caller's own argument, usually the reviewer's, so `signature_a` was keyed on the other party's secret and read as an attestation by the paused agent. It now falls back to an empty key, as the LLM-assisted path has since #2155: `signature_a` stays empty and `describe_attestation` reports the record as `unsigned` (or `single_signer` when only the reviewer signed). A paused agent with a key on file still signs with its own key, and `signature_b` is unchanged. Handler-level tests drive `handle_submit_synthesis` to convergence with a reviewer caller and pin all three cases; two of them fail on the previous code. As of 2026-09-25 no stored peer-path resolution since 2026-01-01 carries a non-empty `signature_a`, because callers pass no `api_key`, so the fix closes the path rather than correcting a stored row. It does not restore party-level key material: with no keys issued, peer-path records stay `unsigned`, which is now what they say. The `describe_attestation` docstring is corrected to match: the four 2026 signatures it counted were the uuid-derived fallback #2155 removed.
