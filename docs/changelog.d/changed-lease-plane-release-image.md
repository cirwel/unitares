- **docker quickstart:** a release checkout no longer has to compile the coordination lease plane. The `Publish Container` workflow now builds a second image from the same release tag, `ghcr.io/cirwel/unitares-lease-plane:vX.Y.Z`, from `elixir/lease_plane/Dockerfile`, with the server image's hardening: pinned action SHAs, `linux/amd64` and `linux/arm64`, SPDX SBOMs, max-mode provenance and a build-provenance attestation. The release commit is baked in as `UNITARES_BUILD_SHA`, so the image's `/health` reports a build sha instead of `unknown`. `Promote Release` verifies that image's digest, platforms, SBOMs and tag-bound provenance next to the server's, re-reads it before promoting and before advancing the install pins, and records it in the release evidence. It never tags the lease plane `latest`. The `lease-plane` service in `docker-compose.yml` names the image with `pull_policy: missing` and keeps its `build:` block. `make version-bump` moves that tag with `VERSION`, so each release tag's tree names the image built from that tag, and promotion refuses a tag whose Compose file names anything else. Until a release publishes the image, the pinned tag does not exist, so Compose prints a pull warning and builds from source as before. A `master` checkout should use `docker compose up --build`, or it runs the last release's lease plane; CONTRIBUTING and the install manual now say so, and the Docker quickstart CI job still builds from source. A new `Lease Plane Image` workflow builds the image for both platforms without pushing whenever the lease plane, `elixir/unitares_sdk` or `publish-container.yml` changes, so the QEMU-emulated arm64 build is exercised on pull requests and a break cannot first appear at release, where it would stop promotion. This changes install time, not lease-plane behavior.
