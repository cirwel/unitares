- **watcher:** The calibration floor that demotes a noisy (pattern, file class) no longer counts resolutions of a rule Watcher has since replaced. `calibration.PATTERN_RULE_VERSIONS` holds the current revision of a pattern's rule, every new finding records its pattern's revision as `rule_version`, and for a listed pattern only findings at the current revision count toward its precision. Findings from before this change, and from a checkout running an older or newer rule, carry a different stamp or none and do not count. A stamp rather than a date, because Watcher state is shared across worktrees and each checkout's hook runs its own `agent.py`. P006 starts at revision 1, the rule after #2424 and #2447 stopped it flagging handlers that already log, re-raise or return an error. As of 2026-09-27, every false-positive dismissal behind the P006 app-code floor came from a 2026-09-23/24 triage of the earlier rule, where most flagged handlers were of the kind those changes dropped, and the floor was hiding current P006 findings on two days in three; that bucket is now unmeasured and does not demote. A change to what a pattern flags should bump its revision, and the P006 rule's comment in `agent.py` says so.
