- **identity check-in thread context:** the `process_agent_update` `thread_context.honest_message` for a `sibling_locus` fork no longer claims "you share a registry UUID … no child UUID minted". That text is false for a `force_new` identity minted onto a thread other processes have occupied, and the check-in path cannot tell that case from a resumed UUID. It now passes `minted_fresh=None` and gets wording true in both cases. The onboard response, which does know, keeps its specific variants. (#2375)
