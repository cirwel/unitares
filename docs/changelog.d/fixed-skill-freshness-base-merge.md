- **ci(skills):** merging master into a branch no longer turns a skill STALE when master re-checked that skill across the source change it brought in after the branch last stamped it. A stamp now records `superseded_digests`, the digests a changed source had been verified at, which says its verifier re-checked the skill across that change. The checker carries a digest certified for the current text forward along transitions recorded after that text's newest certification, even when the stamp that recorded them certified another version of the text; a transition recorded earlier says nothing about the current text and carries nothing. Before this, a branch that edited and stamped a skill went STALE whenever master changed a cited source, even though master had re-stamped its own text against the new content, and every base merge meant another manual re-stamp. Replaying the 19 failing CI runs from 2026-09-24 20:40 to 09-25 08:05 UTC (6 branches) found 29 of 65 STALE sources whose content a stamp had recorded for another version of the skill text, an upper bound on this class. The order is by stamp time, the only order the records carry: a branch that re-stamps after master's re-check and then merges master looks exactly like an unstamped re-land after a revert, and still has to re-stamp. The one pairing given up is the branch's own text edits against master's source change; AGING still bounds it. A revert, a stale branch's stamp of old content, and content no stamp has recorded (a branch's unstamped change, or both sides editing one file) stay STALE. Records written before this carry no transitions, so the relief starts with the next stamps. STALE now lists every drifting source, not only the first. `--prune` keeps every record whose transition leads to a cited source's current content, for any version of the text, so a prune on master does not strand open branches.
