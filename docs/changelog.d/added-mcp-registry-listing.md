- **distribution surfaces: official MCP Registry listing.** UNITARES gets a listing in the official MCP Registry (registry.modelcontextprotocol.io) as `io.github.cirwel/unitares`, where clients and agents increasingly look for servers. `server.json` is metadata only: name, title, the README tagline as its description, repository and website. It deliberately has no package entry. The GHCR server image needs the Compose Postgres (AGE and pgvector) and Redis to start, so a package entry would tell a client to launch something that cannot run on its own; the README's Compose install stays the install path. `.github/workflows/publish-mcp-registry.yml` publishes through GitHub OIDC, so no token or operator login is stored. It runs on every master push that touches `PUBLISHED_VERSION` or `server.json`, stamps the version from `PUBLISHED_VERSION`, skips a version the registry already holds (the registry refuses to republish one), runs only on `refs/heads/master` (a manual dispatch from another ref is skipped, because the OIDC token can publish any `io.github.cirwel/*` entry), and pins `mcp-publisher` v1.8.1 by its release SHA-256. In `docs/operations/distribution-surfaces.toml` the registry moves from `not_listed` to a probed hosted-listing surface, whose `http-ok` probe reads the per-server endpoint and reports DRIFT until the first publish lands.
