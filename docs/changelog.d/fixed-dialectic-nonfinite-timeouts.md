- **dialectic: a nonfinite reviewer timeout no longer breaks orchestrated dispatch.** `inf`, `nan` or `1e309` in a per-host reviewer timeout or in `UNITARES_DIALECTIC_CONTINUATION_WAIT_S` made the spawned reviewer's runtime cap raise `OverflowError` (`ValueError` for `nan`) while the spec was being built, before the dispatcher's own error handling, so the call raised instead of falling back to the in-process reviewer. Such a value now counts as unset and the setting's default applies, both in the cap and in the value forwarded to the reviewer, which would otherwise have passed `inf` to `asyncio.wait_for` and waited on a hung host until the reaper instead of trying the next one. (#2713)

  `float()` accepts all of these spellings, and `1e309` overflows to infinity without any error, so the old parser's `except (TypeError, ValueError)` guard never saw them; only `int()` of the finished cap noticed. One helper, `_seconds()` in `orchestrator_dispatch.py`, now parses every seconds override that feeds the cap, so a new host timeout cannot reintroduce the hole. Negative values keep their previous meaning: a negative host timeout adds no extra lifetime, matching what the reviewer itself does with it, and a negative continuation wait still falls back to the default window so it cannot disable the orchestrator's reaper. The per-host half arrived with the reviewer host list (#2652); the continuation-wait half was already on master. Regression tests cover each spelling for both settings and pin that the spec still builds.
