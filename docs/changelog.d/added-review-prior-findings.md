- **review:** a local review of a new diff now also checks the findings the previous round left unanswered.
  - **Why:** a push answers a finding without recording what became of it. Over 30 merged PRs checked on 2026-09-26, 88% of findings ended that way. The written dispositions were therefore a biased remainder, mostly rebuttals, because an agreed finding is usually fixed by a push rather than disposed.
  - **When it applies:** the last completed round, on an earlier diff, raised findings and nobody disposed them.
  - **What happens:** `review.sh` quotes that round into the prompt, for Claude, Codex and Antigravity alike. The reviewer reviews the change on its own first. It then reports each earlier finding as `RESOLVED`, `STILL-PRESENT` or `UNCLEAR` in a `PRIOR-FINDINGS:` block placed before the VERDICT line. The posted record carries the counts in a hidden `unitares-review-prior v1` line naming the earlier diff key, so the outcome can be read without re-scraping the pull request.
  - **Who judges:** the reviewer does, and when the providers allow it is a different model from the author, so this is not the author's self-report.
  - **What stays the same:** the review's status still comes from its VERDICT alone, and a still-present finding counts only because the reviewer must also list it as its own. A failed run posts no counts. Native Codex rounds and the capped fix-verification path do not change.
  - **Caveat:** quoting earlier findings may steer the new review toward them. The prompt orders the independent review first, but that ordering is an instruction, not a guarantee.
