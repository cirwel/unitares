- **identity: a strict-mode onboard that declares lineage is no longer refused.** Under `STRICT_IDENTITY_REQUIRED`, an `onboard` or `start_session` call with no ownership proof and no `force_new` is refused with `lineage_declaration_required`, and the refusal's hint names two ways forward: pass `parent_agent_id` to continue prior work, or pass `force_new=true` for a fresh process-instance. The first of those did not work. The freshness gate counted only ownership proofs, a caller-asserted session id or a display name as signals, so a call that followed the hint with `parent_agent_id` and `spawn_reason="explicit"` but no `force_new` was refused again by the same gate, before it reached the later check that does permit declared lineage. A declared `parent_agent_id` now passes that gate and is promoted to `force_new=true`, because a declared-lineage onboard is a fresh mint by definition; the later lineage checks, such as `lineage_coincidental_rejected` for a live parent, still apply. A bare call with neither field is refused as before, and the permissive posture is unchanged.
