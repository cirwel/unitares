- **write timeouts:** a tool call that can write no longer answers its timeout with advice to try again. The `@mcp_tool` timeout ends the wait for the reply, not the work. On 2026-09-27 an `update_finding` on the AGE backend returned `TIMEOUT` with "Try again with simpler parameters" after its row had committed, and because `resolution_notes` append, following that advice writes them twice. The timeout reply for a write, admin or unclassified call now says the outcome is unknown and the change may have been saved. It carries `outcome: "unknown"`, `operation`, `call_started_at` and `settled_by` (the reply time plus the pool's 30 s command timeout, after which a statement still running at the timeout has finished; no recovery step resends before it), and its recovery names the read that settles the question before any retry: `knowledge(action='details', discovery_id=...)` for a knowledge update, where an `updated_at` earlier than the call's start means nothing landed and a later one sends the caller to look for its own fields; `describe_tool` for other writes; and, for a store or note, a queryless `knowledge(action='search')` filtered to the author the handler records (the bound identity, the anonymous `anonkg_*` pseudonym, or the `agent_id` the call passed) and to rows created between `call_started_at` and `settled_by`, newest first, archived and cold rows included, limit 100, which needs no bound identity (`check_arguments` carries it as arguments). A relevance search could lose the row off its ranked page and match another writer's row with the same summary. The window lookup reads `knowledge.discoveries` on both backends, so a list below the limit is every row that author created in the window; the reply says when the author id is not the caller's alone, and then only an absent row is proof. `onboard` (and `start_session`) and `identity` are listed as reads but can create an identity, so their timeouts get this reply too, with a recovery that says a repeat creates another identity. The class comes from the `operation` metadata that `describe_tool` already reports, resolved per router action. `error_code` stays `TIMEOUT`, `error_category` stays `system_error`, and read tools keep the reply they had. On the AGE backend a windowed query whose SQL read fails now raises instead of returning no rows, as the postgres backend already did, so a failed read is not taken for an empty window; semantic search's in-memory fallback, which only ranks candidates, still degrades to none, so a hybrid search keeps its full-text results. Separately, the AGE update no longer waits for the embedding refresh it runs after committing. The first embedding in a process imports sentence-transformers and loads the model, and that load is what outlasted the 10 s timeout in the incident; the refresh now runs as a tracked background task, one pass at a time per discovery so an older pass cannot store stale text last (#2543).
