- **Archive, delete and resume act only for the agent itself or an operator.** `agent(action="archive"|"delete"|"resume")` reaches its handlers through a tool that may name another agent as the target, and the handlers did no check of their own, so any bound caller could archive, delete or unpause any other agent (GHSA-r9q5-7j8h-82rr). They now require the session binding to resolve to the target, or the request to carry a valid `X-Unitares-Operator` token from `UNITARES_OPERATOR_TOKENS`; a bearer API key alone, an unbound caller, and a token not on the allowlist are refused with `LIFECYCLE_NOT_OWNER_OR_OPERATOR` and the target is left as it was. `operator_resume_agent` keys on the same token instead of the caller's own `operator` label or tag, both of which were self-claimed at onboard, and `operator` is now a server-granted tag that `update_agent_metadata` refuses. The Lumen check-in doctor presents `UNITARES_OPERATOR_TOKEN` on its resume of Lumen, which was the only cross-agent caller of these actions found. Interface contract 1.28.0: no schema or digest changes, the version records the behavior change (#2667).
