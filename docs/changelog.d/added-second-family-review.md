- **review gate:** a diff that touches a security-sensitive path now needs a passing review from two different model families before the `review` check goes green. The paths live in `scripts/dev/review_policy.json`: the OAuth provider, identity and auth modules, `access.py`, the strong-model host adapter and Antigravity client, the dialectic reviewer's backends, and the review gate, its policy file and its workflow. Families are OpenAI (Codex, native or local), Anthropic (Claude) and Google (Antigravity); a reviewer recorded with `review.sh record` counts by its name. A passing review is `CLEAN`, or `FINDINGS` whose dispositions are all recorded, and open findings still block exactly as before. `review.sh` adds the second review itself when a sensitive diff has only one family's pass, choosing a reviewer from a family that has not passed yet, and reports UNREVIEWED when none is available. CI reads the policy from the base branch, as it already does the gate, so a pull request cannot take itself off the list. The motivating cases: on PR #2486 the first reviewer returned a bare CLEAN and a second family then found two P2 defects, and the Antigravity isolation hole (standing permission grants loaded from `~/.gemini`) was caught by one family's review.
