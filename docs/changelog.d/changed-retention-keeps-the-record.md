- **retention:** `audit.partition_maintenance()` no longer deletes anything except expired sessions (migration 073). It used to delete every `core.agent_state` check-in older than 90 days except each identity's latest, and drop `audit.events` months older than 180 days, `audit.tool_usage` older than 90 and `outcome_events` older than 365, both on its weekly run and whenever an outcome insert found its partition missing. On the reference deployment, running since November 2025, that left check-ins from 2026-07-08 onward only. Check-ins and outcome events are now kept. Old `audit.events` and `audit.tool_usage` months move to `scripts/ops/archive-audit-partitions.py`: a dry run by default, `--export` writes each month to a gzipped CSV under `~/backups/archive/audit-partitions/` with a manifest (rows, sha256, source table and a content fingerprint taken in the export's own snapshot), and `--apply` drops a month only after its archive has been read back and counted, and only if the partition's OID and fingerprint still match under an exclusive lock, so a change between export and drop stops the drop. Nothing schedules the script yet, so those two tables grow until an operator runs it. The drop and cleanup functions remain for that script and for deliberate manual use. The migration is opt-in at deploy, like every migration.
