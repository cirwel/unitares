- **knowledge writes bound the rest of the text they send to the graph; supersede applies its `resolution_notes`:** on the AGE backend every value a write stores goes through `GraphMixin._sanitize_cypher_param`, which refuses a string, or a dict serialized with `json.dumps`, over 128 KiB. #2530 bounded `details` on update; the other caller-controlled values were still unbounded. An update's `summary` or `tags` over that limit rolled the whole update back and the caller was told `Discovery '<id>' not found`; a store's tags or node metadata (`related_files`, the provenance fields a call sends such as `memory_context`, a batch item's `provenance`) failed with the sanitizer's own "Cypher dict param too long" text. Each is now refused with `INVALID_PARAM` before anything is written, with a recovery naming what to shorten: an update's `summary` above 4,003 characters (`MAX_SUMMARY_LEN` plus the `...` a store appends when it truncates, so a stored summary sent back unchanged still passes); more than 50 tags or a tag over 128 characters, counted after normalization, on store, batch store, note, promote and update; and node metadata over 32 KiB as the AGE store serializes it, on store, batch store (as that item's error), note and promote. The limits live in `src/mcp_handlers/knowledge/limits.py`. `knowledge(action='supersede')` listed `resolution_notes` but never read them, so the notes were dropped. They are now appended to the older finding's details in the same update that marks it superseded, exactly as an update appends them, within the same 96 KiB details bound; on a high or critical finding only its owner may send them, matching update's rule that a non-owner adds notes there only while closing it as resolved, closed or wont_fix. A supersede without notes behaves as before (#TBD).
