- **consult:** every consultation that reaches the router now writes one `audit.events` row, `event_type='consultation'` (`unitares.consultation_record.v1`), recording the requester, policy, outcome, the route when a well-formed result came back, and HMAC-SHA256 hashes of the brief, prompt and advice. The brief and advice are never stored as text. The hash key is per-consultation, returned only to the caller in the new `record.hash_key` response field, and never stored, so readers of the row cannot test a guessed brief while the caller can prove which row is theirs. Any bound agent can read the row through `observe(action='audit_events')`. It is written to Postgres only, with `confidence=0.0`, so it stays out of the JSONL readers and confidence readers that take an agent's recent rows without an event-type filter. What it does not claim: it does not cover `call_model` or `delegate_inference`; it does not replace or mark the `auto_attest` decision that Energy accounting already writes for each successful call; an upstream failure records no route; and an identifier-shaped piece of the brief that a backend echoes into a model name or execution id is stored as reported (#2477).
