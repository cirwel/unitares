- **repo scope guard:** the guard no longer names one contributor in its own detection patterns. `scripts/dev/check-repo-scope.sh` Rule 3 now flags any personal webmail address (Gmail/Googlemail, Yahoo, Hotmail, Outlook, Live, iCloud, Proton/ProtonMail at `.com` or `.me`) instead of one literal address, and a new Rule 8, with the PR-body check in `.github/workflows/repo-scope.yml`, flags any machine-absolute `/Users/<name>` home path except illustrative placeholder names (`/Users/you`, single letters, `testuser`, `/Users/Shared` and similar) instead of one account's path. On PR bodies the home-path match ignores case, as the old check did, so a lowercase `/users/<name>/...` is still caught; the home-path check still runs on PR bodies that carry the allow-register marker. The guard's messages no longer point at one machine's directory layout. `docs/REPO_SCOPE.md` documents both patterns and the placeholder list.
