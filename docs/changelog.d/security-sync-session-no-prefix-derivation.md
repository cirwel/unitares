- **A session key no longer resolves by its shape.** The synchronous identity lookup (`_get_identity_record_sync`, behind `get_bound_agent_id` when no request context has bound an agent) treated any key starting with `agent-` as a uuid prefix: it looked the rest up in the prefix index and, failing that, scanned agent metadata and bound the key to the first agent whose uuid started with it. So `agent-a` resolved to whichever agent's uuid began with `a`, and `agent-` to any agent at all, with no stored binding and no proof, and the lookup cached the result and recorded the caller's fingerprint as the binding's. A key now resolves only through a binding stored for it, which is what the async resolver already required. Callers reach this path for diagnostics and audit labels (`list_process_bindings` without an `agent_uuid`, lifecycle audit entries, `record_progress_pulse` before its explicit fallback); a request whose identity middleware already bound an agent is unaffected, because the bound agent wins first.
