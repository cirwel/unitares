- **identity: a pre-onboard self-read never shows state from a binding the server only inferred; unbound reads say why; a claimed name replaces a knowledge write's auto-name; name hints carry the session:** (1) Three paths that served a server-inferred binding's real state to a proof-less `check_working_state` / `get_governance_metrics` are closed. On `/mcp/` the sticky transport binding is no longer consulted for a pre_onboard read: it ran ahead of the #945 short-circuit, so a connection that sends its own `Mcp-Session-Id` (Claude Code subagents share the parent's) or a UDS caller on the bare fingerprint read whichever agent last resolved there, directly and through `use_tool`. On `/mcp/` an `agent_uuid` argument (reachable only through `use_tool`) and a UUID `X-Agent-Id` header no longer count as read proof: the derivation ignores both, so such a read resolved on the onboard pin or the connection's session and served that binding, not the named agent. On REST a body with a null or empty `client_session_id` and no session header no longer reaches the sticky binding. Such reads now return the unbound payload. Writes are unchanged: they still use the sticky binding, which the strict write gate treats as server-inferred. A read that carries proof (the caller's `client_session_id`, an `X-Session-ID` header, a verified `continuity_token`) reads as before. In the 14 days of `audit.tool_usage` before the change, one pre-onboard read without a caller-sent session id was served from a binding, by the agent this batch uses for its probes; the count covers the recorded transports only. (2) The unbound read's `next_action` is keyed on why nothing bound, with the recovery the strict refusal gives for the same resolver result: a session lookup that raised (`pg_lookup_exception`) or a resolver failure is retried with no onboarding offered, and a hijack-guard rejection, a substrate resident reading over REST or a token naming an inactive agent is named with its reason, where both used to be told their id "names no identity" and offered a rebind or a mint. The payload then carries `unbound_reason` with the keys the strict refusal puts in its `surface_context`. A read without proof and a plain session miss get the same recovery as before. The server-failure texts shared with the strict refusal now say "a missing identity" and "mint" instead of using "onboard" as a verb, and the hijack-guard hint says "Mint a new identity with" instead of "Re-onboard with". (3) After a knowledge write names an agent `Agent_<uuid8>`, a later claim (`identity(client_session_id=..., name=...)` or a name on a check-in) is the name displayed, and `label_source` reads `claimed`; it used to keep showing the auto-name as `auto`. (4) Thirteen recovery, onboarding and description hints that showed `identity(name='...')` now show `identity(client_session_id='...', name='YourName')`, since a name alone lets identity() resolve a co-located agent; the argument-less `identity()` steps in the same recovery patterns are gone too. (5) Interface contract 1.21.0, numbered after 1.20.0 (the closure-class PR): tool descriptions only. `check_working_state` and `get_governance_metrics` say which proof reads your own state and that an inferred binding is never read; `/mcp/` drops `agent_id`, and through `use_tool` or REST it names the agent to read, which `check_working_state` marks `caller_proven=false` when the call's session was only inferred. No input digest or the surface digest moves (#TBD).
