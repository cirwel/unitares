- **oauth:** an authorization code now yields at most one token pair. `exchange_authorization_code` removed the code with `pop(code, None)` and went on to mint tokens whether or not the code was still there, while `load_authorization_code` only reads. Two `/token` requests carrying the same code could therefore both pass the load and both receive valid access and refresh tokens, contrary to RFC 6749 section 4.1.2, which requires an authorization code to be used once. In the current asyncio flow nothing between the load and the exchange appears to suspend, so the window may be narrow or unreachable in practice, but the guarantee now holds by construction: the exchange claims the code before minting anything, exactly as `exchange_refresh_token` already claims its refresh token, and a second redemption gets `invalid_grant` ("authorization code already used") with no token issued. Also fixes the server's startup error line, which printed a literal `\n` before `❌ Error:` because the source escaped the backslash. Both defects were found by the Antigravity reviewer (Gemini 3.1 Pro) in the changed files of an unrelated PR during the file-mode review experiment. (#2458 follow-up)
