- **knowledge search:** `recency_half_life_days` on `knowledge(action="search")` and `search_shared_memory` is an opt-in recency weight, off by default (operator decision, 2026-09-27). With a query, each result's relevance is multiplied by `0.5 ** (age_days / recency_half_life_days)` before authority ranking, so a result that many days old keeps half its score and a fresh match can overtake an older, slightly stronger one. It is a true half-life. The AGE backend's own blend on the semantic leg is `1 / (1 + age / 90)`, which is also 0.5 at 90 days but decays more slowly after that, and it still applies underneath. The weight reads the same score authority ranking reads (cross-encoder, then RRF, then semantic similarity, then a full-text row's rank, then position). RRF is rank-derived and nearly flat, so on a hybrid search the weight dominates the order. Authority ranking still applies on top, and the candidate pool widens to the same 50 rows so a fresh match just below the first page can be retrieved to be lifted. It is refused with `sort_by="created_at"`, which already orders by time, and without a query, where results are already newest first. The response echoes it. Accepted values are above 0 and at most 36500 days. Interface contract 1.23.0; to stay inside the progressive tool-listing ratchet, `search_shared_memory`'s `include_details` brief and `knowledge`'s `sort_by` brief are shortened (full descriptions unchanged). What it does not claim: no default half-life is set or recommended, and no retrieval evaluation backs any particular value; the retrieval eval's labels have decayed and cannot currently score one.
