- **dialectic:** a thesis no longer comes back as a failure, with `request_review` saying it was not recorded, when the spawned independent reviewer claims the slot and then exits non-zero inside the fast-crash wait, or when the dispatch call times out after the reviewer was spawned. The in-process fallback's facilitation request is refused in both cases because the session moved on; the handler now re-reads the session and reports the recorded thesis with the reviewer and phase it finds. If that reviewer already committed a terminal failure, or a decision whose durable effect is not confirmed applied, the call reports it as unsuccessful with the same failure fields and reconciliation guidance as the synthetic-timeout path, still with `thesis_recorded: true`. When the reviewer that holds the slot exited inside the fast-crash wait and the session is still live, the handler records the facilitation request against the re-read session (`reviewer_exited: true`, `awaiting_facilitation: true`), and `request_review` names an operator or a replacement reviewer as the next to move, never the exited reviewer; if that session changed again first, the call reports `state_reload_required`. If the re-read shows no other writer, the call reports `state_reload_required` with `thesis_recorded: true` instead. Nothing is dispatched twice, and the only write after the refusal is that facilitation request (#2905).
