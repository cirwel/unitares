- **identity / host observations:** a context compaction can now be recorded. `POST /v1/runtime/observe` accepts `observation_kind="context_compaction"` on the same identity-bound terms as the other kinds (a live `client_session_id` bound to `agent_uuid`). It is stored as `runtime_observation.context_compaction` in `audit.events` and writes no EISV. It never refreshes the session, even when the payload carries tool counts, and it stays out of the runtime-activity read model. New read-only `scripts/diagnostics/compaction_outcomes.py` (logic in `src/identity/compaction_outcomes.py`) pairs each recorded compaction with what followed: `minted` (a `spawn_reason="compaction"` child), `kept` (the identity's own check-in, knowledge read or write, or consult; rows others write against it, such as `agent_archived`, do not count) or `no_later_activity`. It pages through every compaction and says so when its cap leaves the read incomplete. A compaction without a usable binding cannot be recorded, so it does not appear. The plugin's SessionStart hook is the reporter, in a companion plugin PR. This is the follow-up approved with the 2026-10-22 compaction decision (#3003).
