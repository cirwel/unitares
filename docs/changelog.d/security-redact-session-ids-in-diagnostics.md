- **Diagnostics no longer hand out other sessions' ids.** A `client_session_id` is a bearer credential: whoever presents it acts as the session it names. `list_process_bindings` accepts any `agent_uuid` and returned, for each live process bound to that agent, the `client_session_id` it onboarded with, so any caller could read another agent's session id and use it. `admin(action='debug_context')`, open to any bound caller, listed up to ten raw keys from the in-memory session cache and up to ten 12-character uuid prefixes, and such a prefix is the legacy `agent-{uuid12}` session id itself. Binding rows now carry `client_session_ref`, an opaque reference: it reveals no character of the id and is keyed with a secret held only by the server process, so it cannot be presented and is no oracle for guessing ids offline. References are stable for the life of the process, enough to tell rows apart. The debug view shows the same references, and reports the uuid prefix index only by its size. Interface contract 1.29.0 records the output change; no input schema moves. Nothing internal read either value, so concurrency detection and lineage checks are unchanged.
