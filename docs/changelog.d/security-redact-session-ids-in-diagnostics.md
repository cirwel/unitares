- **Diagnostics no longer hand out other sessions' ids.** A `client_session_id` is a bearer credential: whoever presents it acts as the session it names. `list_process_bindings` accepts any `agent_uuid` and returned, for each live process bound to that agent, the `client_session_id` it onboarded with, so any caller could read another agent's session id and use it. `admin(action='debug_context')`, open to any bound caller, listed up to ten raw keys from the in-memory session cache and up to ten 12-character uuid prefixes, and such a prefix is the legacy `agent-{uuid12}` session id itself. Binding rows now carry `client_session_ref` (the first eight characters and a digest), which tells rows apart and matches a session you already hold but cannot be presented. The debug view shows the same references and cuts uuid prefixes to eight characters. Interface contract 1.29.0 records the output change; no input schema moves. Nothing internal read either value, so concurrency detection and lineage checks are unchanged.
