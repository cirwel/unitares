- **agent archive and delete need a named target over REST too:** #2532 made `agent(action='archive')` and `agent(action='delete')` refuse a call that names no `agent_id` instead of acting on the caller, but only on `/mcp/`. Every REST prebind path (`/v1/tools/call`, and `use_tool` nested under it: the operator token, the sticky binding and the session binding) wrote the resolved caller into an omitted `agent_id` before the handler ran, so over REST such a call still archived or deleted the caller. The prebind now reads whether the call named a target before any path writes one, and for the calls `/mcp/`'s identity step leaves alone (`_EXPLICIT_TARGET_CALLS`, including the `archive_agent` and `delete_agent` aliases and `op=`) it takes the stamp off again once the caller is bound, so the handler refuses with `TARGET_AGENT_REQUIRED`. Other calls keep the session default. A REST caller that archived or deleted itself by leaving `agent_id` out now gets `TARGET_AGENT_REQUIRED` and passes its own UUID, as on `/mcp/`. Whether `agent(action='resume')` should follow the same rule is an open decision; because the REST prebind now reads the shared call set, adding resume there would apply it on both transports.
