- **knowledge search:** `knowledge(action="search")` and `search_shared_memory` take `sort_by`, `created_after` and `created_before`. `sort_by="created_at"` returns the query's full-text matches newest first: the database orders the match set by `created_at`, so an entry written a minute ago comes first however weakly it ranks, where re-sorting a relevance page would only reorder rows that already ranked in. Status, archived/cold exclusion, type, severity and author filters sit inside that ordered query too, so newer ineligible matches cannot fill the page. It uses no semantic leg, reranker or authority reorder, and it refuses `search_mode="semantic"` or `"hybrid"`, because similarity has no match boundary to order within. `created_after` / `created_before` are exclusive ISO 8601 bounds (UTC when no offset is given), applied inside the query on every retrieval path (full-text, filter reads, and the pgvector similarity search, which joins the discovery row as the tag filter already did); an unparseable or inverted window is refused, not ignored. With no query, `created_after` is the "what is new since T" read, newest first. Responses echo `sort_by` and the window when they differ from the default, the lean digest included. The default order is unchanged. `exclude_agent_labels` is now checked while candidates are collected rather than after the page is cut, so an excluded writer no longer leaves a page short in either order. `search_shared_memory` pays for the three fields with shorter advertised briefs on nine existing search parameters (full descriptions unchanged through `describe_tool`), so the progressive tool listing is smaller than before. Interface contract 1.22.0. All three fields were previously stripped by the unified `knowledge` schema; the legacy `search_knowledge_graph` schema declared `sort_by` (default `created_at`) and both bounds, and no handler read any of them. That default is now `relevance`, and its never-implemented `score` and `related_count` values are refused. What it does not claim: newest-first recall is the full-text match set, so an entry that shares no query terms (after stemming) is not returned, and the AND-then-OR fallback applies as it does for relevance search.
