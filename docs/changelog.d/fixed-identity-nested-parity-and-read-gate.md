- **identity: a target named through `use_tool` resolves as it does named directly; the REST read gate judges headers as `/mcp/` does; refusals and `label_source` stop pointing at a second identity:** (1) The nested `/mcp/` `use_tool` path no longer copies the transport session (an `X-Session-ID` header, `Mcp-Session-Id`, the OAuth or `X-Client-Id` client, or the IP:UA fingerprint) into a session-injected target's `client_session_id`, flagged transport-injected. A direct call never did, since FastMCP None-fills the argument first. So a header-only `sync_state` through `use_tool` now derives `x_session_id` / caller-asserted and passes `STRICT_IDENTITY_REQUIRED` as it does directly, a proof-less `check_working_state` through `use_tool` reads `unbound` instead of resolving a server-inferred binding and serving its state, and a fingerprint-only write reaches the step-7 onboard pin. An explicit outer `client_session_id` still reaches the target as caller input. (2) The REST pre-onboard read gate no longer counts an `X-Client-Id` / `X-MCP-Client-Id` header as proof: it names a client, not a process, so two processes of one client could read each other's state. Both read gates now judge a transport header through one predicate (`transport_session_is_read_proof`), under which only `X-Session-ID` proves a read. A `client_session_id` the caller sent and a verified `continuity_token` still prove it. REST writes are unchanged. No caller in this repo, the governance plugin, the discord bridge, anima-mcp or the host adapter sends `X-Client-Id`, and no pre-onboard read in `audit.tool_usage` over the 14 days to 2026-09-26 carried a session id of the shape one would produce. (3) The strict refusal for a required call that resolved no identity (`session_resolve_miss` on `/mcp/`, an unbound required call on REST) no longer leads with `onboard(force_new=true)`. With no `client_session_id` of the caller's own on the call, it leads with retrying with the id `start_session` returned, then the `identity(agent_uuid, continuity_token, resume=true)` rebind, and offers a mint only to a process that never called `start_session`. With a caller-sent id that names nothing, the rebind leads and the mint is for a process with nothing to rebind to. Both transports build it from `identity_bootstrap`, which now also holds the recovery sentences the strict write refusal and the unbound read quote (their text is unchanged). The bare-onboard lineage refusal keeps its mint-first defaults. (4) `agent_signature` and the knowledge display payload report the label the mint assigns (`claude_code-opus_<uuid8>`, logged as `[AUTO_NAME]`) as `label_source: "auto"` instead of `"claimed"`. The mint records that label (`auto_label` in the identity metadata), and a label is server-assigned while it still equals the record, so a claimed name renamed `<name>_<uuid8>` by a collision still reads `claimed`. Agents minted earlier, and lazily persisted mints, carry no record and read as before. No tool description or input schema changed (#TBD).
