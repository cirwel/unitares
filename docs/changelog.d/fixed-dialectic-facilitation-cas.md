- **dialectic: the stuck-session sweeper no longer flags a session that just made progress as awaiting facilitation.** The sweeper read the stuck set and later wrote `awaiting_facilitation`, guarding only terminal status, so a participant message landing in between still got the session flagged, fired `dialectic_facilitation_needed`, and could leave the flag set on a session that was not stalled. The write is now a compare-and-set on the `phase` and `updated_at` the sweeper observed (both ANTITHESIS and SYNTHESIS stalls); a row that moved on is refused like any other refused sweeper write and re-read next sweep. The write still never touches `updated_at`. (#2367)

  The race was inherited from the ANTITHESIS `reviewer_unresponsive` path and was widened in reach when the SYNTHESIS `synthesis_stalled` entry was routed through the same shared write block, so one change to `DialecticDB.mark_awaiting_facilitation` and its sweeper call site covers both phases. Callers that pass no expected values, such as tests or tools that want the unconditional guarded write, get exactly the previous behaviour. The caller-driven `update_session_awaiting_facilitation` handler writer is unchanged: it is a deliberate transition on a live session and still bumps `updated_at`. Regression tests simulate a participant message and a phase move landing between the sweeper's read and its write, for both phases, and pin the new SQL predicate at the database layer.
