- **dialectic:** new resolutions no longer receive v2 party-HMAC signatures, on any finalize path: peer-review synthesis, the synthetic reviewer in `submit_thesis`, and LLM-assisted dialectic. The scheme was symmetric and keyed on api_keys the server stores, so a party HMAC the server computed attested only that the server wrote the row, which the attributed row already says; restoring key issuance would also have revived a deprecated credential. Minting stops inside `DialecticSession.finalize_resolution`, which now takes no api_key at all, rather than by relying on keys being absent, and no handler looks a key up for it. The stored shape is unchanged: `signature_a` and `signature_b` stay present and empty, so the record's key set, the `Resolution.hash()` formula served as `resolution_hash`, and the field set a `drr.v1` receipt covers are the same, and tests pin the hash of an unchanged record. New rows carry `signature_version` 3, so a record read on its own says why it is unsigned. `describe_attestation` reports such a row as `unsigned` with a new `unsigned_by_design` flag, which is false on every historical row. History is never stripped or backfilled, no migration runs, and historical rows classify exactly as before; `compute_signature` and `verify_signatures` stay for reading them. The offline receipt verifier now distinguishes an unsigned record from a single-signer one instead of warning "single-signer" for both. Party-level non-repudiation remains a goal whose lever is agent-held asymmetric keys, which is not scheduled. Decision D5 in `docs/proposals/active/federation-trust-decisions-2026-09-25.md` (#2449).
