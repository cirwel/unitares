- **local model:** `UNITARES_MODEL_ID` has no default any more. Through v3.4.0 an unset `UNITARES_MODEL_ID` fell back to `gemma4:latest`, a model the operator may never have pulled and which, inside a container, usually reached nothing. Unset, the local lane now has no model and sends nothing: `consult` (standard lane) and the deprecated `call_model` with `model='auto'` refuse with the new code `MODEL_NOT_CONFIGURED` before any request; the in-process and orchestrated dialectic reviewers abstain with that reason in their provenance, so the review waits for a peer or the operator as it already did when no model answered; internal enrichments (check-in coaching, knowledge synthesis) are skipped; `agents/local_resident` raises `ModelNotConfiguredError`; and `scripts/client/ollama_bridge.py` exits asking for `--model`. A caller that passes an explicit `model` is unaffected. `list_inference_hosts` reports `ollama:local` with an empty `models` list and a note saying so. `unitares model` no longer preselects gemma; it offers the first model the server lists. **To keep the old behaviour, set `UNITARES_MODEL_ID=gemma4:latest`** in `.env` or the LaunchAgent plist, or run `./scripts/unitares model`. The doctor already warned about an unnamed model and now says it is refused.
