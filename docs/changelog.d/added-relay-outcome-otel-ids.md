- **sdk:** outcome events filed by the NeMo Relay integration now carry `otel_trace_id` and `otel_span_id` in their `detail`. These are the W3C ids of the trace and span that Relay's own OpenTelemetry export writes for the scope the outcome is about. An evaluator who sends Relay's spans to any OTLP store (Langfuse, Phoenix, Jaeger) can find the span behind a UNITARES outcome without this server's tooling. The ids are derived from Relay 0.8.4's scope-UUID mapping, not observed. A test against the real runtime checks them against the bytes Relay exports over OTLP. Like the existing end-to-end test, it skips when the extra is absent, and no CI lane installs it today, so a Relay upgrade must be checked locally with the extra installed. No schema, tool or server change. This is the join test the 2026-09 claims audit's "no standard emission" gap called for; it is not an OpenTelemetry exporter for UNITARES records, which remains an operator decision.
