- **A low- or medium-severity `store_finding` from a caller the server only inferred no longer writes as the agent it inferred.** Dispatch fills `agent_id` from the session binding even when that binding is server-inferred (transport fingerprint, onboard pin, transport-injected `client_session_id`, context fallback). Every client behind one address with one User-Agent shares a fingerprint, so on a Docker bridge or behind a tunnel a fresh connection that passed no `client_session_id` had its findings credited to whichever agent last matched. A cold-start install test found this when a second connection's finding landed on the first connection's agent. Such writes now take the stable anonymous writer id (`anonkg_*`) that the tool description already promised for unbound callers, the same rule knowledge reads and the strict write gate apply. Callers that prove their session (`client_session_id`, `Mcp-Session-Id`, `X-Session-ID`, OAuth or `X-Client-Id`, continuity token) are unaffected, and high or critical stores still require a registered agent.
