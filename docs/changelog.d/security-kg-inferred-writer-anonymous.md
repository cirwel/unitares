- **A knowledge write from a caller the server only inferred no longer writes as the agent it inferred.** Dispatch fills `agent_id` from the session binding even when that binding is server-inferred (transport fingerprint, onboard pin, transport-injected `client_session_id`, context fallback). Every client behind one address with one User-Agent shares a fingerprint, so on a Docker bridge or behind a tunnel a fresh connection that passed no `client_session_id` had its findings credited to whichever agent last matched. A cold-start install test found this when a second connection's finding landed on the first connection's agent. Low- and medium-severity stores, notes and updates on such a binding now take the stable anonymous writer id (`anonkg_*`) that the tool description already promised for unbound callers. Under strict identity, a high or critical store or update on such a binding is refused with the strict check-in gate's `identity_required` refusal, which tells the caller to retry with its `client_session_id`. Agents the strict check-in gate exempts (substrate-earned, or `dedicated_substrate`) keep their attribution, decided by the same predicate the gate uses, which fails closed. Callers that prove their session (`client_session_id`, `Mcp-Session-Id`, `X-Session-ID`, OAuth or `X-Client-Id`, continuity token) are unaffected.
