- **observe:** `observe(action="agent")` resolves the handle `agent(action="list")` prints for a non-operator caller, and no longer returns the registry UUID to that caller. The listing shows `{public_agent_id}_{uuid8}` in place of the UUID, but the resolver compared the target with the unsuffixed stored id, so the printed handle answered "not found in active metadata" for an agent that had checked in the same day. Separately, a target that resolved by label came back with its full UUID in `agent_id`, which undid the listing's redaction with one more read. The returned id now goes through the listing's disclosure rule (`lifecycle.disclosure.visible_agent_identifier_for_caller`): the operator and the observed agent get the UUID, a caller who passed the UUID gets it echoed, anyone else gets the handle with `uuid_redacted: true`. A non-operator client that read a UUID out of an observe-by-label response now receives a handle. The `target_agent_id` description is unchanged, and the other observe actions were not audited for the same gap (#2736).
