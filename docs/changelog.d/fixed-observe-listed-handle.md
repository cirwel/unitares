- **observe:** `observe(action="agent")` resolves every identifier `agent(action="list")` prints for a non-operator caller, no longer returns the registry UUID to that caller, and no longer picks one agent when a target names several. The listing shows `{public_agent_id}_{uuid8}` in place of the UUID, but the resolver compared the target with the unsuffixed stored id, so the printed handle answered "not found in active metadata" for an agent that had checked in the same day. The resolver now compares against exactly what the listing prints (`lifecycle.disclosure.listed_agent_identifier`), including the `agent-redacted-<digest>` fallback. Separately, a target that resolved came back with its full UUID in `agent_id`, which undid the listing's redaction with one more read. The returned id now goes through the listing's disclosure rule (`lifecycle.disclosure.visible_agent_identifier_for_caller`) with no exception: the operator and the observed agent get the UUID, anyone else gets the listed identifier with `uuid_redacted: true`, including a caller who passed the UUID. Resolution has a fixed order: the UUID, then a listed identifier the server composed, then an alias (label, display name, structured id, bare `public_agent_id`). A label is chosen by the agent that wears it, so a label set to another agent's handle neither receives nor blocks that agent's lookups. An alias names its one live holder ahead of archived or deleted ones, so a label shared by an archived predecessor and its live successor resolves to the successor whatever order the registry holds them in. A target that still names more than one agent (two live holders of a label, the bare bucket `public_agent_id`, two agents whose UUIDs share a first block) is refused with `AMBIGUOUS_TARGET`, where the first matching registry row used to be returned; the refusal points the caller at the identifier the listing prints. Behavior changes for callers: a non-operator client that read a UUID out of an observe response now receives a handle, and a lookup by a label or bucket id that several agents share now fails where it used to answer for one of them. The interface contract moves 1.31.0 → 1.32.0 to record this; no input digest moves. Not covered: `observe` `similar` and `anomalies` still return peer UUIDs, and knowledge-graph search results carry writer UUIDs, so the listing's redaction is not yet a boundary on every surface (#2736).
