- **`identity(force_new=...)` reads its flag consistently, and the identity handler passes it to the resolver (#2692).** The `identity` tool read `force_new` without coercion, so a string `"false"` from an MCP client counted as true: the call skipped its session-key resume and minted a fresh identity against the caller's intent. The adapter and the handler now coerce the flag the same way. The handler also skipped its session-key resume for `force_new` and then resolved the same key without passing it, so the resolver ran checks that belong to a resume; since keyed session ids (#2702) such a check can return a refusal, which the handler then read as an identity and failed on. `force_new` now rides through to the resolver, which mints without consulting the key. Through the public tool path nothing changes for a forged or refused session id: the identity middleware validates the presented id before any handler runs and refuses it with `stable_session_id_rejected`, `force_new` or not, so a tampered credential is refused rather than replaced by a fresh identity. Calls without `force_new` are unchanged.
