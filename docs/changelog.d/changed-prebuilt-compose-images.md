- **docker quickstart:** a release checkout now pulls prebuilt images for the server (`ghcr.io/cirwel/unitares`) and the database (`ghcr.io/cirwel/unitares-postgres`, Postgres with Apache AGE and pgvector), as it already did for the lease plane, so `docker compose up -d --wait` builds nothing locally. Each service keeps its build block: a missing tag, or `--build`, builds from the checked-out source, and CI's Docker quickstart still builds from source. `Publish Container` publishes the database image from the same tag with the same hardening, and no published release tag is replaced by a re-dispatch any more (previously only the lease plane's was kept). `make version-bump` moves all three pins. `Promote Release` verifies the database image wherever the tagged Compose file pulls one and requires the tagged file's server and database pins to name that release; a release cut before this change builds both locally and still promotes. A new `Postgres Image` workflow builds the database image for both platforms on pull requests that change it. `unitares update` still rebuilds from source. The first release that publishes the database image needs its GHCR package made public once.
