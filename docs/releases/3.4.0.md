# UNITARES v3.4.0

A minor release from master, following v3.3.0 (2026-10-08). The interface
contract moves from 1.31.0 to 1.49.0 without leaving major version 1: no tool,
action or input is removed or renamed, and the one retyped input (`host_id` on
`consult` and `delegate_inference`, from an enum to a bounded string) accepts
every value it accepted before. Several behaviors change; each is listed below
with the step or setting it needs, where one exists. Five database migrations
land, and two of them make rollback forward-only. The full list of changes is
the [3.4.0 changelog entry](../CHANGELOG.md); this page covers what an operator
needs to upgrade, what an existing install will notice, and what is not
claimed.

## Upgrade order

Apply the migrations before any 3.4.0 process starts, with the writers stopped.

1. **Before you start**, with v3.3.0 still running, check that no dialectic
   resolution saga is in flight. This should return 0:
   `SELECT count(*) FROM coordination.session_resolution_sagas WHERE state IN ('reserved', 'paused_agent_applied', 'both_agents_applied', 'reverting');`
   These states are transient in a running deployment; let v3.3.0 finish them
   first. Drain every live file-write executor too, and do not run old and new
   executors side by side.
2. **Docker Compose.** The `scripts/unitares update` in a v3.3.0 checkout is
   the v3.3.0 script. It cannot pass the attestation that migrations 077 and
   078 require, so its upgrade refuses and rolls back to v3.3.0. Move the code
   once by hand and let the 3.4.0 script do the rest:

   ```bash
   git fetch --depth 1 --no-tags origin "+refs/tags/v3.4.0:refs/tags/v3.4.0"
   git checkout --detach v3.4.0
   docker compose up -d --build --wait postgres-age
   ./scripts/unitares update --to v3.4.0
   ```

   The 3.4.0 `update` stops `governance-mcp` and `lease-plane`, writes a backup
   (to `~/.unitares/backups` unless `UNITARES_BACKUP_DIR` says otherwise),
   applies migrations 074 to 078 with the attestation, then starts the new
   images. Do not start the 3.4.0 server or lease plane any other way before
   the migrations are applied. If `update` stops before migration 077 is
   applied, it restarts the stack from the checked-out 3.4.0 Compose file; to
   run the v3.3.0 images instead, check out v3.3.0 and run
   `docker compose up -d --wait`. Once 077 or 078 is applied, it keeps both
   writers stopped for forward repair.
3. **Operator install.** Follow the frontier rollout order in
   [`docs/operations/lease-plane-operator-runbook.md`](../operations/lease-plane-operator-runbook.md):
   block dialectic submissions and stop both writer runtimes, back up the
   database (for example with `scripts/ops/backup_governance.sh`), apply the
   migrations, restart the Python server on 3.4.0, then the lease plane on the
   same revision, verify both revisions, and only then restore dialectic
   traffic. With both writers stopped,
   `python3 scripts/dev/apply_migrations.py --apply --dialectic-writers-quiesced`
   applies the migrations. Without the flag the run refuses before applying
   anything while 077 or 078 is pending; with it, the run refuses at 077 while
   a resolution saga is in flight, after 074 to 076 have applied. Apply the
   migration files only through `apply_migrations.py` or `unitares update`:
   loading them with `psql -f` skips both checks.
4. **Every install needs migration 076 before the 3.4.0 lease plane starts:**
   its lease queries read 076's column even with execute flags off. Retained
   reservations and their recovery are described in
   [`docs/operations/effect-custody-recheck.md`](../operations/effect-custody-recheck.md).
5. **Native BEAM services** (the agent orchestrator, and a lease plane started
   by `start.sh`) keep their Erlang cookie off the command line from their next
   restart. The Compose lease plane does not start through `start.sh`.

If an upgrade refuses on an in-flight saga anyway, bring v3.3.0 back up so its
writers can finish or revert it, then run the upgrade again. If a saga stays in
flight, stop and investigate: this release ships no tool that reconciles a saga
while both writers are stopped.

| Migration | What it adds |
|---|---|
| 074 | knowledge change notices |
| 075 | dialectic resolution effects |
| 076 | effect custody reservations for file writes |
| 077 | dialectic transcript revisions |
| 078 | dialectic resolution saga revisions; drops the old same-payload uniqueness constraint |

## Rollback

Before migrations 077 and 078 are applied, return to v3.3.0 by checking it out
and starting its images (`git checkout --detach v3.3.0`, then
`docker compose up -d --wait`). `unitares update --to v3.3.0` refuses as soon
as the database schema is newer than v3.3.0's last migration, 073.

**Once 077 or 078 has been applied, recovery is forward-only.** v3.3.0's Python
sweepers are not generation-fenced, and its BEAM writer relies on the
uniqueness constraint that 078 removes, so v3.3.0 code must not run on the
migrated schema. `scripts/unitares update` refuses an automatic code rollback
across that frontier and leaves both writers stopped. Going back after that
means replacing the database with its pre-upgrade state. `update` writes a
gzipped plain-SQL dump before migrating, but no shipped command restores it,
and a dump that has never been restored is unverified. An install that needs a
guaranteed way back should snapshot its Postgres volume before upgrading, as
[`TROUBLESHOOTING.md`](../guides/TROUBLESHOOTING.md) advises.

## What an existing install will notice

- **Verdict mix for behavioral agents.** Two repairs to the EISV decision path
  change which policy action a warmed behavioral agent receives. The basin now
  reads S against the same setpoint Φ uses, and the Φ-derived fast-trip is
  skipped when the behavioral assessment owns the verdict (#2831); the ODE's E
  and I equations read S − σ (#2834). Expect more `proceed`
  (`sub_action: approve`) where `guide` used to appear. #2834 also moves
  physical-sensor rows from the BOUNDARY basin to HIGH. The changelog gives
  each estimate with its own method and limits: #2831's is a one-step replay of
  14 days of persisted inputs that does not model the closed loop; #2834's is
  an equilibrium-shift estimate over the same frozen export that models
  neither the transient nor the closed loop, and depends on how many rows the
  Φ fast-trip still covers. Rows from either side of each change belong to
  different instrument eras: new rows carry `state_json.eisv_instrument`, and
  the era-guarded analysis readers refuse a window that crosses a change unless
  given a reason.
- **Lineage needs a declared `spawn_reason`.** The server no longer infers
  `subagent` or `compaction` from thread context or `client_hint`. An onboard
  that passes `parent_agent_id` without `spawn_reason` is recorded as
  `new_session`; while that parent is live, the lineage is rejected
  (`rejected_coincidental`) and the identity is minted without it. No setting
  restores the inference: a dispatched child passes `spawn_reason="subagent"`.
  `unitares onboard` and `scripts/client/onboard_helper.py` no longer declare
  the cached identity as parent.
- **`observe(action="agent")` redacts for other callers.** A caller that is
  neither the operator nor the observed agent gets the identifier the agent
  listing prints instead of the UUID, and a target that names more than one
  agent is refused with `AMBIGUOUS_TARGET`.
- **A paused agent cannot resume itself with `agent(action="resume")`.** It
  gets `PAUSE_SELF_RESUME_REFUSED` and the same recovery block a paused write
  gets. `self_recovery`, dialectic, an operator, a safety net and expiry still
  end a pause, and an operator token still resumes a paused agent. An expired
  pause reports writes held until its token-fenced resume commits; state reads
  expose `expiry_eligible` separately.
- **Archived, disabled, deleted and paused proposers are vetoed** by
  `POST /v1/effect-veto` on every path, including the unknown-proposer branch.
- **CIRS auto-emit runs again.** The void-alert, state-announce and resonance
  emitters had not fired since 2026-03-09; they now fire on check-ins.
- **Knowledge search ranks by semantic relevance before fusion.** Semantic and
  hybrid search no longer down-weight resolved, older or weakly linked records
  before fusion, so results reorder and `similarity_scores` carry the cosine
  score; pass `recency_half_life_days` for a recency preference.
  `search_shared_memory`'s lean and compact tiers list further results under
  `more_results` when `limit` is unset (pass a `limit` of 3 for the old shape),
  and its hints name `use_tool(tool_name='knowledge', ...)`.
- **Imported memory is classified only by `source-<provider>-memory` tags.**
  Queryless knowledge listings and check-in memory suggestions omit unpromoted
  imported memory; `authority_mode='all'` or a `source-<provider>-memory` tag
  filter still reads that lane, and query search is unchanged.
- **Health reports a missing Postgres extension.** When `age`, `vector`,
  `pgcrypto` or `pg_trgm` is absent, `health_check` and `/health/deep` report
  overall `status: moderate` (was `healthy`), with `primary_db` among the
  degraded checks and `status: degraded` and `missing_extensions` in its info.
- **`call_model` is deprecated.** It still works and is removed no earlier than
  2026-12-02. Move callers to `consult(effort='standard')`, which reaches the
  same local host; `call_model`'s model, temperature and max_tokens controls
  retire with it. The SDK's `call_model()` emits a `DeprecationWarning`.
- **Inference host discovery lists configured hosts.** `list_inference_hosts`
  returns only configured hosts by default; `include_unconfigured=true` returns
  the full inventory. The SDK's default follows.
- **The local fallback reviewer no longer approves when reviewer hosts are
  set.** When orchestrated dispatch fails and a reviewer host list (or a
  `dialectic_reviewer` job in the inference hosts file) is set, the session
  waits for facilitation instead. With no list, or the local floor named as the
  single host, the fallback runs as before.
- **Codex lanes run with reads denied.** The codex host adapter and the
  dialectic reviewer's codex backend run under a generated permission profile
  that denies reads outside the runtime's own paths. An administrator codex
  configuration refuses the lanes, and a codex that does not honor permission
  profiles refuses rather than runs unconfined.

## Compatibility

- **Interface contract 1.49.0.** Every step from 1.31.0 adds surface or records
  a documented behavior change. New surface includes replayable knowledge
  notices (1.35.0), host selection and diagnostics for `consult` (1.36.0,
  1.37.0, 1.41.0), the operator-only `dialectic(action="reconcile_effect")`
  and the `reviewed_work_author_agent_ids` review parameter (1.47.0), and
  `response_to` on `store_finding` (1.48.0). See
  [`docs/INTERFACE_CONTRACT.md`](../INTERFACE_CONTRACT.md).
- **Python, Compose and dependencies.** The Python floors are unchanged.
  `docker-compose.yml` changes only its three image tags, which now name
  v3.4.0. `constraints.txt` pins `mcp==2.3.0` (was 2.2.0); an existing
  environment keeps its installed version until it is reinstalled with the pin.
- **`unitares-sdk` 0.5.0** is published from this release commit. It is a
  behavioral minor over 0.4.0, as 0.3.0 and 0.4.0 were, and removes nothing
  public. Since 0.4.0 it negotiates progressive tool listings on connect and
  sends calls to unadvertised tools through `use_tool`, fills
  `CheckinResult.metrics`, adds `consult()`, `ConsultResult` and a `retry`
  keyword on `call_tool`, sends `consult()` and `delegate_inference()` once
  without retrying, raises `GovernanceToolRefused` from the sync client too,
  adds the lease plane's `effect_in_progress` result, carries Relay's
  OpenTelemetry trace and span ids on outcome events, narrows
  `list_inference_hosts()` to configured hosts, and deprecates `call_model()`.
  The v3.2.0 and v3.3.0 trees declared an in-tree 0.4.1 that was never
  published; this release skips that number so that one version names one
  artifact.
- **Governance plugin.** This release's skills bundle is cut as plugin v0.4.21.

## Evidence and known limits

- The EISV repairs are numerical and decision-path fixes. They make no claim
  about outcome prediction. The 2026-12-01 registered outcome read is amended
  after interim exposure: it admits only outcomes before the first instrument
  change (2026-10-15T13:45:00Z), so no outcome recorded under these repairs
  enters it.
- `observe`'s redaction is not yet a boundary on every surface:
  `observe(action="similar")`, `observe(action="anomalies")` and
  knowledge-graph writer fields still carry peer UUIDs.
- A file-write reservation coordinates cooperating writers. It is not an OS
  sandbox and does not cancel a filesystem operation already admitted.
- Container images, SBOMs and provenance are verified by the Promote Release
  workflow after publication; `latest` moves only after that verification.
- `scripts/unitares update` runs the copy of itself that the install already
  has, so a release whose migrations need a new update step needs the manual
  checkout above. Handing over to the target release's copy is follow-up work.
