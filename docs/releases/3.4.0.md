# UNITARES v3.4.0

A minor release from master, following v3.3.0 (2026-10-08). The interface
contract moves from 1.31.0 to 1.49.0 without leaving major version 1: no tool,
action or input is removed, renamed or retyped. Five database migrations land,
and two of them change how a rollback works. The full list of changes is the
[3.4.0 changelog entry](../CHANGELOG.md); this page covers what an operator
needs to upgrade, what an existing install will notice, and what is not
claimed.

## Upgrade order

Apply the migrations before any 3.4.0 process starts, with the writers stopped.

1. **Docker Compose:** run `scripts/unitares update`. It stops
   `governance-mcp` and `lease-plane`, starts the database, writes a backup
   (to `~/.unitares/backups` unless `UNITARES_BACKUP_DIR` says otherwise),
   applies migrations 074 to 078, then starts the new images. Do not start the
   3.4.0 images with a bare `docker compose up` before the migrations are
   applied.
2. **Operator install:** stop the governance server and the lease plane, block
   dialectic traffic, back up the database, then run
   `python3 scripts/dev/apply_migrations.py --apply --dialectic-writers-quiesced`.
   The flag attests that both the old Python and BEAM dialectic writer and
   liveness runtimes are stopped; migrations 077 and 078 refuse without it.
   They also refuse while any dialectic resolution saga is still in flight:
   reconcile or revert those with both writers stopped, then retry.
3. **File-write executors:** drain every live file-write executor before the
   upgrade and do not run old and new executors side by side. The 3.4.0 lease
   plane reads migration 076's column even with execute flags off, so it must
   not start on an unmigrated database. Retained reservations and their
   recovery are described in
   [`docs/operations/effect-custody-recheck.md`](../operations/effect-custody-recheck.md).
4. **Native BEAM services** (agent orchestrator, lease plane started by
   `start.sh`) keep their Erlang cookie off the command line from their next
   restart. The Compose lease plane does not start through `start.sh` and is
   unaffected.

| Migration | What it adds |
|---|---|
| 074 | knowledge change notices |
| 075 | dialectic resolution effects |
| 076 | effect custody reservations for file writes |
| 077 | dialectic transcript revisions |
| 078 | dialectic resolution saga revisions |

## Rollback

Before migrations 077 and 078 are applied, roll back by checking out v3.3.0 as
usual. **Once 077 or 078 has been applied, recovery is forward-only.** v3.3.0's
Python sweepers are not generation-fenced, and its BEAM writer assumes a
uniqueness constraint that 078 removes, so v3.3.0 code must not run on the
migrated schema. `scripts/unitares update` refuses an automatic code rollback
across that frontier and leaves both writers stopped. To return to v3.3.0
after it, restore the database backup taken before the upgrade, then check out
v3.3.0. A failed upgrade is otherwise repaired forward on 3.4.0.

## What an existing install will notice

- **Verdict mix for behavioral agents.** Two repairs to the EISV decision path
  change which policy action a warmed behavioral agent receives: the basin now
  reads S against the same setpoint Φ uses, and the ODE's E and I equations
  read S − σ. Expect more `approve` where `guide` used to appear. The changelog
  entries give the replay estimates with their limits: one-step replays of
  persisted inputs that model neither the transient after a restart nor the
  closed loop. Rows from either side of each change belong to different
  instrument eras: new rows carry `state_json.eisv_instrument`, and the
  era-guarded analysis readers refuse a window that crosses a change unless
  given a reason.
- **`observe(action="agent")` redacts for other callers.** A non-operator caller
  gets the identifier the agent listing prints instead of the UUID, and a
  target that names more than one agent is refused with `AMBIGUOUS_TARGET`.
- **A paused agent cannot resume itself with `agent(action="resume")`.** It gets
  `PAUSE_SELF_RESUME_REFUSED` and the same recovery block a paused write gets.
  `self_recovery`, dialectic, an operator, a safety net and expiry still end a
  pause; an operator token still resumes a paused agent.
- **Archived, disabled, deleted and paused proposers are vetoed** by
  `POST /v1/effect-veto` on every path, including the unknown-proposer branch.
- **Health reports a missing Postgres extension.** `health_check` returns
  `status: degraded` with `missing_extensions` when `age`, `vector`,
  `pgcrypto` or `pg_trgm` is absent, where it used to report `healthy`.
- **`call_model` is deprecated.** It still works and is removed no earlier than
  2026-12-02. Move callers to `consult(effort='standard')`, which reaches the
  same local host; `call_model`'s model, temperature and max_tokens controls
  retire with it. The SDK's `call_model()` emits a `DeprecationWarning`.
- **Inference host discovery lists configured hosts.** `list_inference_hosts`
  returns only configured hosts by default; `include_unconfigured=true` returns
  the full inventory. The SDK's default follows.
- **Queryless knowledge listings omit unpromoted imported memory**, and so do
  check-in memory suggestions. `authority_mode='all'` or an imported-memory tag
  filter still reads that lane; query search is unchanged.
- **The local fallback reviewer no longer approves when reviewer hosts are
  set.** When orchestrated dispatch fails and a reviewer host list (or a
  `dialectic_reviewer` job in the inference hosts file) is set, the session now
  waits for facilitation instead of being resolved by the local floor.
- **Codex lanes run with reads denied.** The codex host adapter and the
  dialectic reviewer's codex backend run under a generated permission profile
  that denies reads outside the runtime's own paths. An administrator codex
  configuration refuses the lanes, and a codex that does not honor permission
  profiles refuses rather than runs unconfined.

## Compatibility

- **Interface contract 1.49.0.** Every step from 1.31.0 is additive or records
  a documented behavior change. New surface includes replayable knowledge
  notices (1.35.0), host selection and diagnostics for `consult` (1.36.0,
  1.37.0, 1.41.0), the operator-only `dialectic(action="reconcile_effect")`
  and the `reviewed_work_author_agent_ids` review parameter (1.47.0), and
  `response_to` on `store_finding` (1.48.0). See
  [`docs/INTERFACE_CONTRACT.md`](../INTERFACE_CONTRACT.md).
- **Python and Compose.** The Python floor is unchanged. `docker-compose.yml`
  changes only its three image tags, which now name v3.4.0.
- **`unitares-sdk` 0.4.1** is published from this release commit. It adds
  `consult()` and `ConsultResult`, sends `delegate_inference()` and
  `consult()` once without retrying, carries Relay's OpenTelemetry trace and
  span ids on outcome events, and deprecates `call_model()`. It was declared in
  v3.2.0 and is a patch on 0.4.0: nothing is removed, and the one changed
  default (`list_inference_hosts`) matches the server.
- **Governance plugin v0.4.21** carries this release's skills bundle.

## Evidence and known limits

- The EISV repairs are numerical and decision-path fixes. They make no claim
  about outcome prediction. The 2026-12-01 registered outcome read is amended
  to admit only outcomes before the first instrument change
  (2026-10-15T13:45:00Z), so no outcome recorded under these repairs enters it.
- `observe`'s redaction is not yet a boundary on every surface:
  `observe(action="similar")`, `observe(action="anomalies")` and knowledge-graph
  writer fields still carry peer UUIDs.
- A file-write reservation coordinates cooperating writers. It is not an OS
  sandbox and does not cancel a filesystem operation already admitted.
- Container images, SBOMs and provenance are verified by the Promote Release
  workflow after publication; `latest` moves only after that verification.
